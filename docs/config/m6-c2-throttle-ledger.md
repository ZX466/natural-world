## 1. 降频门取证台账

### 1.1 九笔样本（全部实测，非转述）

| # | 轮次 | `burst_base_ms` | `sustained_worst_ms` | **`throttle_ratio`** | `throttled` | `samples` |
|---|---|---|---|---|---|---|
| 1 | C13（bench 全量内） | — | — | **2.197** | true | — |
| 2 | C13（bench 全量内） | — | — | **2.345** | true | — |
| 3 | M6-C1 | 15.536 | 41.278 | **2.657** | true | 1244 |
| 4 | M6-C2 ① | 16.615 | 39.519 | **2.379** | true | 1059 |
| 5 | M6-C2 ② | 18.396 | 38.849 | **2.112** | true | 987 |
| 6 | M6-C2 ③ | 17.146 | 38.542 | **2.248** | true | 1231 |
| 7 | M6-C2 ④ | 18.235 | 35.775 | **1.962** ✅ | **false** | 1277 |
| 8 | M6-C2 ⑤ | 16.165 | 38.237 | **2.365** | true | 1378 |
| 9 | M6-C2 ⑥ | 19.222 | 39.513 | **2.056** | true | 1288 |

> #1/#2 取自 C13 bench 全量的 soak 降频自检 skip 文案（该轮两次自跳过），非本轮新测。

### 1.2 统计

| 指标 | 值 |
|---|---|
| 样本数 | **9** |
| `≤ 2.0`（过门） | **1 笔（#7 = 1.962）** ⇒ 命中率 **1/9 ≈ 11%** |
| `> 2.0`（未过） | 8 笔 |
| min / median / max | **1.962 / 2.248 / 2.657** |
| 幅度 | max−min ≈ **0.70**；median 距门限仅 **+0.248** |

### 1.3 判定：**临界态**（既非持续态、也非回落）

| 候选判定 | 是否成立 | 反证／证据 |
|---|---|---|
| **纯持续态**（恒不过门） | ❌ **不成立** | #7 实测 `1.962`、**`throttled: false`** ⇒ **已证明能过门** |
| **纯回落**（已恢复且稳定） | ❌ **不成立** | #7 之后 #8 = 2.365、#9 = 2.056 **又回到门限上方** ⇒ 非单调恢复 |
| **临界态**（在门限两侧摆动） | ✅ **成立** | median 2.248 距门限仅 +0.248，9 笔中 1 笔越过 ⇒ **贴线抖动** |

> **⚠ 对 M6-C1 的修正**：C1 我写的是「本机持续降频是**跨轮持续态，不是偶发**」。按本轮取证，**该措辞过强**——准确表述是「**本机是临界机，比值在 2.0 两侧摆动；9 笔中 1 笔可过门**」。「从未低于 2.0」这一隐含前提**已被 #7 推翻**。

### 1.4 对定标门判据的影响（**建议报 pi / Claude 裁决**）

| 项 | 现状 | 问题 |
|---|---|---|
| P13 §2.1 门 2 判据 | 「`throttle_ratio ≤ 2.0`」**单笔**判 | 本机单笔命中率 ≈ **11%** ⇒ 按现判据派单等于**抛硬币**；且**结果会flap**（今天过、下一轮不过） |
| 建议 | 改判「**连续 N 笔（建议 N=3）均 ≤ 2.0** 才派定标」，并把 N 笔原始值一并写进回执 | 让门有**滞回**，避免临界机在门槛上抖动导致反复改判 |
| 另一条正路 | 修机（散热/电源/后台负载）而非改判据 | median 2.248 本身偏高；`burst_base_ms` 在 **15.5–19.2ms** 间摆（本身抖动），`sustained_worst_ms` 稳定在 **35.8–41.3ms** ⇒ **持续段被限、突发段未限**，是典型的热/功耗封顶特征 |

## 2. M6 首波后的 CI 面基线（**soak 阶段 A 冒烟面仍绿**）

> 前提说明：**M6 首波尚未落地**——`main` 仍为 `48c9944`（M5 收官态），`git log HEAD..main` 为空；`test_bench_soak.py` 内**零** `BOUND`/`SOAK_ENTITY_LOSS_PER_GAME_DAY` ⇒ **阶段 A 未施工**。故本节是**「阶段 A 前」的基线**，供 M6 首波合入后逐项对照。

### 2.1 当前 CI 面（实测）

| 项 | 值 |
|---|---|
| 入口 | `.github/workflows/ci.yml:58` `uv run pytest -m "not bench"`（step 名 `:51`「pytest（T1/T2/T3；排除 bench）」） |
| 冒烟本体 | `test_bench_soak.py:202` `test_soak_ci_smoke_stability`——**无 `@pytest.mark.bench`** ⇒ 每提交跑 |
| 冒烟断言面 | `:217` → `_assert_smoke(result, label="M2 长跑 CI 冒烟", expected_ticks=_CI_SOAK_TICKS)`；`:150` docstring：「**只验『可跑通 + 实体集稳定 + 总 tick 到位』**」，且注明裁 28-D/M5-P5 已收口为「**不判漂移、不判稳态均值、不判资源增长**」 |
| **基线实测（健康 runner 模拟）** | `PI_THROTTLE_SELFCHECK=0` + 单测 ⇒ **`1 passed in 3.44s`** ✅ |

### 2.2 阶段 A 将改的确切行（**对照锚点**）

当前 `_assert_smoke` 的实体集判据在 **`test_bench_soak.py:163-165`**：

```
assert result.entity_count_end == result.entity_count_start, (
    f"{label}: 实体数漂移 {result.entity_count_start} → {result.entity_count_end}"
)
```

阶段 A（P14 §2.1）会把这一处由 **`==`** 改为**两侧界**（`end <= start` **且** `start - end <= BOUND`，`BOUND=0`）。
⇒ **基线锚点＝`L163`**；M6 首波合入后**只需核这一行**即可判「阶段 A 已落且语义等价」。
**预期**：因 `BOUND=0` 两式合起来恰为原 `==`，**CI 冒烟面应仍 `1 passed`**；若首波后此面转红，按 P14 §5 次序红线处理（**契约必须先于生命机制落地**）。

### 2.3 判读纪律（沿用 M6-C1，本轮复验仍成立）

本机降频时冒烟测试被**设计内自跳过**（`:200` throttle 门）⇒ **验 CI 断言面必须带 `PI_THROTTLE_SELFCHECK=0`**；
否则会把 **skip 误读成绿**，或把 skip 误读成红而白排查一轮。
