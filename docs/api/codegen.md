# OpenAPI → shared/protocol.ts 生成管线（docs/api/codegen.md）

> 能力域：接口 / 兼容性（kilo） | 对齐 DESIGN.md §4 §5 §19
> 本文为**设计文档**。落地实现由依赖/配置域（cline）协作；本文件锁定管线契约与 CI 守卫。

## 1. 一句话契约

**协议类型只从 FastAPI OpenAPI 自动生成，绝不手写**（§4 工具链、§19 禁止事项）。
真相源 = sim 端 pydantic v2 模型（§4「唯一真相源」）；生成物 = `shared/protocol.ts`；前后端共用同一份生成物。

## 2. 真相源到类型物的链路

```
sim/api/*.py  (pydantic v2 模型：HTTP 请求/响应 + WS 信封 + 各 WS 消息 data)
        │  FastAPI 启动时聚合
        ▼
  /openapi.json   (OpenAPI 3.1，FastAPI 默认路径；当前含 HTTP 请求体，WS 消息待 sim 侧 custom_openapi 补全)
        │  openapi-typescript
        ▼
  shared/protocol.ts  (单一生成物)
        │
   ┌────┴────┐
   ▼         ▼
client/src/net   client/src/ui   (前端唯一类型入口)
```

- HTTP 路由 → FastAPI 标准 OpenAPI 生成（`response_model`/`body`）。
- **WS 消息**不天然进 OpenAPI。方案：把 WS 信封与各 `*.data` 模型注册为 OpenAPI **独立 components/schemas**（FastAPI 可用一条隐藏路由的 `response_model` 或自定义 `components` 注入，实现细节归 cline）。`openapi-typescript` 会为每个 schema 生成 TS 类型，WS 与 HTTP 类型落在同一文件，前端一处导入。

## 3. 目录方案（前后端共用一个生成物）

```
shared/
├─ protocol.ts        # 生成物（唯一）—— 前端 import；后端不依赖此文件（后端用 pydantic）
├─ openapi.json       # schema 快照：M0 阶段为手写 mock（sim 未起服务）；sim 起后由 FastAPI 导出替换
tools/
└─ gen-protocol.ts   # 生成脚本：openapi-typescript + banner + prettier + --check（kilo 维护）
```

- 后端 sim 不引用 `protocol.ts`（它有 pydantic 源类型）；`protocol.ts` 纯服务前端，避免 Python↔TS 双向漂移。
- 前端 `client/src/net`（WS）与 `client/src/ui`（React/HTTP）均从 `shared/protocol.ts` 导入类型，禁止在 `client/` 内另写协议类型；`client/src/net/protocol.ts` 只做 re-export + 判别联合别名。

## 4. 生成命令

```bash
# 在 client/ 下执行（复用其 node_modules）；任一处均可
npm run gen:protocol           # 生成 shared/protocol.ts（banner + prettier 已含）
npm run gen:protocol:check     # CI 漂移检测：生成到临时文件比对，不一致则非零退出
```

- 工具 `tools/gen-protocol.ts` 调用 `client/node_modules/.bin/openapi-typescript`（`--immutable --export-type --alphabetize`），注入 banner，再经 `prettier --config client/.prettierrc.json` 格式化，写 `shared/protocol.ts`。
- `--immutable`：生成 `readonly` 字段，契合 §6 实体 frozen / 不可变更新约定。
- `--export-type`：输出 `type` 而非 `interface`，便于联合判别（WS `type` 字段的字面量联合 + discriminator）。

**真实源对齐（K03 已完成，2026-09-20）**：

- sim 的 OpenAPI 地址是 **`http://127.0.0.1:8000/openapi.json`**（FastAPI 默认；**不是** `/api/openapi.json`）。
- `shared/openapi.json` 已按 sim 真实形状对齐（抽查 ProfileCreate/ProfileUpdate 约束：name 1–64、temperature 0–2 默认 0.7、max_tokens 1–32768 默认 2048）。
- **重要缺口**：sim 当前 OpenAPI **仅含 HTTP 请求体** —— 既无 WS 消息（`WsMessage`/`state_delta`/…），也无响应模型（`ProfileListItem`/`WorldMapResponse` 等，因路由返回 `dict[str, Any]` 而非 `response_model`）。故 `shared/openapi.json` 同时承担「sim 未导出部分（WS 消息 + 响应契约）」的协议契约，由本域维护。
- **sim 侧待补**（归 Claude 架构域，切换彻底化的前置）：`sim/api/main.py` 加 `custom_openapi` 注入 WS 消息 components；settings 路由加 `response_model`（`ProfileListItem`）。补全后 `npm run gen:protocol -- --src http://127.0.0.1:8000/openapi.json` 可直接产出完整生成物。
- 对齐校验命令：
  ```bash
  uv run uvicorn sim.api.main:app --port 8000   # 需 LZ_MASTER_KEY（codex K2）
  npm run gen:protocol -- --src http://127.0.0.1:8000/openapi.json
  ```
  逐字段比对与 `shared/openapi.json` 的差异，以 sim 为准回写（HTTP 请求体）；WS/响应契约以本快照为准。
### 4.1 切源暂缓声明（M2-C4 落档，2026-09-22；裁决依据 kilo M2-K2 复核）

> **结论：`--src` 切真实源当前不可用；mock 快照 `shared/openapi.json` 继续当唯一真相源。**
> 本节为防误切声明——上方「真实源对齐」的 `--src` 命令**仅可作对齐校验参考**，其产出**不得**提交为
> `shared/openapi.json` / `shared/protocol.ts`。

- **原因（P0，kilo M2-K2 复核结论）**：sim 当前 OpenAPI 缺 **21 个 HTTP 子结构 schema**（路由返回
  `dict[str, Any]`、无 `response_model`），且 WS 消息 components 只存在于本域快照中。对真实源跑
  `openapi-typescript` 只能产出缺 21 schema + WS 全量契约的残缺类型——切源 = 前端类型静默劣化。
- **解除条件（两项齐备，经 Claude 裁决后方可解禁）**：
  1. sim HTTP 路由补齐 `response_model`（21 个缺失 schema 的来源路由清单 = kilo M2-K3 交付物，照单施工）；
  2. openapi_ext（`shared/openapi.json`）对齐快照返工完成（WS 消息 components 注入真实形状）。
- 补全前跑 `npm run gen:protocol -- --src http://127.0.0.1:8000/openapi.json` 仍会「跑通」，但产物缺
  21 schema + WS 类型；若误提交，CI 漂移闸（§5 第 1 道）会以 mock 源口径比对出漂移而拦截——勿存侥幸。

## 5. CI 守卫：「协议类型未手写」

三道闸（任一失败即 CI 红）：

1. **漂移检测**：CI 跑 `npm run gen:protocol:check`（`tools/gen-protocol.ts --check`：生成到临时文件与已提交的 `shared/protocol.ts` 比对）。不一致 → 失败信息「协议生成物与 schema 源不一致，请 `npm run gen:protocol` 重新生成并提交」。接入 `ci.yml` 归 cline。
2. **banner 校验**：`shared/protocol.ts` 首行必须为 `// AUTO-GENERATED by openapi-typescript — DO NOT EDIT (see docs/api/codegen.md)`；用 grep 守卫，缺失即失败。
3. **手写禁令**：ESLint 规则禁止对 `shared/protocol.ts` 的直接编辑（配合 `no-edit` 注释 + pre-commit 钩子；落地归 cline）。

> 对应 §19「不要手写 shared/protocol.ts，从 OpenAPI 生成」——CI 把这条禁止事项变成可执行门禁。

## 6. 前端使用示例（仅类型，不含逻辑）

```ts
import type { components, schemas } from "@/shared/protocol";

type WsEnvelope = schemas["WsEnvelope"];                 // 信封
type StateDelta = components["schemas"]["StateDelta"];    // WS 增量
type ProfileListItem = components["schemas"]["ProfileListItem"]; // HTTP 响应
```

- 联合判别靠 `channel`/`type` 字面量联合，switch 收窄，避免手写 any。

## 7. 增删协议字段的流程

1. 改 sim 端 pydantic 模型（唯一真相源）。
2. 跑 `npm run gen:protocol`，本地验证 `shared/protocol.ts` 变更符合预期。
3. 提交 `sim/api/*.py` + `shared/openapi.json` + `shared/protocol.ts`（三者同一次提交，否则 CI 漂移闸失败）。
4. 如改了 WS 消息集合，同步更新 `versioning.md` 的版本号。
