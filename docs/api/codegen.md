# OpenAPI → shared/protocol.ts 生成管线（docs/api/codegen.md）

> 能力域：接口 / 兼容性（kilo） | 对齐 DESIGN.md §4 §5 §19
> 本文为**设计文档**。落地实现由依赖/配置域（cline）协作；本文件锁定管线契约与 CI 守卫。

## 1. 一句话契约

**协议类型只从 FastAPI OpenAPI 自动生成，绝不手写**（§4 工具链、§19 禁止事项）。
真相源 = sim 端 pydantic v2 模型（§4「唯一真相源」）；生成物 = `shared/protocol.ts`；前后端共用同一份生成物。

## 2. 真相源到类型物的链路

```
sim/api/*.py  (pydantic v2 模型：HTTP 请求/响应 + WS 信封 + 各 WS 消息 data)
        │  FastAPI 启动时聚合
        ▼
  /api/openapi.json   (OpenAPI 3.1，含 components/schemas：HTTP 与 WS 一并)
        │  openapi-typescript
        ▼
  shared/protocol.ts  (单一生成物)
        │
   ┌────┴────┐
   ▼         ▼
client/src/net   client/src/ui   (前端唯一类型入口)
```

- HTTP 路由 → FastAPI 标准 OpenAPI 生成（`response_model`/`body`）。
- **WS 消息**不天然进 OpenAPI。方案：把 WS 信封与各 `*.data` 模型注册为 OpenAPI **独立 components/schemas**（FastAPI 可用一条隐藏路由的 `response_model` 或自定义 `components` 注入，实现细节归 cline）。`openapi-typescript` 会为每个 schema 生成 TS 类型，WS 与 HTTP 类型落在同一文件，前端一处导入。

## 3. 目录方案（前后端共用一个生成物）

```
shared/
├─ protocol.ts        # 生成物（唯一）—— 前端 import；后端不依赖此文件（后端用 pydantic）
├─ openapi.json       # 提交进库的 schema 快照（CI 可复现，见 §4）
└─ .generated-banner  # 生成头模板
```

- 后端 sim 不引用 `protocol.ts`（它有 pydantic 源类型）；`protocol.ts` 纯服务前端，避免 Python↔TS 双向漂移。
- 前端 `client/src/net`（WS）与 `client/src/ui`（React/HTTP）均从 `shared/protocol.ts` 导入类型，禁止在 `client/` 内另写协议类型。

## 4. 生成命令

```bash
# 1) 导出 schema 快照（CI 与本地一致；不依赖运行中的服务器）
uv run python -m sim.api.main --export-openapi shared/openapi.json

# 2) 生成类型
npx openapi-typescript shared/openapi.json -o shared/protocol.ts \
  --immutable --export-type

# 3) 一步到位（package.json script: "gen:protocol"）
npm run gen:protocol
```

- `--immutable`：生成 `readonly` 字段，契合 §6 实体 frozen / 不可变更新约定。
- `--export-type`：输出 `type` 而非 `interface`，便于联合判别（WS `type` 字段的字面量联合）。
- 生成物头部注入 banner（见 §5），`openapi-typescript` 支持 `--comment` 或后处理脚本追加。

## 5. CI 守卫：「协议类型未手写」

三道闸（任一失败即 CI 红）：

1. **漂移检测**：CI 重新跑 `gen:protocol`，对 `shared/protocol.ts` 与 `shared/openapi.json` 做 `git diff --exit-code`。若有差异 → 失败信息「协议生成物与 pydantic 源不一致，请重新生成并提交」。
2. **banner 校验**：`shared/protocol.ts` 首行必须为 `// AUTO-GENERATED by openapi-typescript — DO NOT EDIT (see docs/api/codegen.md)`；用 grep 守卫，缺失即失败。
3. **手写禁令**：ESLint 规则禁止对 `shared/protocol.ts` 的直接编辑（配合 `no-edit` 注释 + pre-commit 钩子；落地归 cline）。

> 对应 §19「不要手写 shared/protocol.ts，从 OpenAPI 生成」——CI 把这条禁止事项变成可执行门禁。

## 6. 前端使用示例（仅类型，不含逻辑）

```ts
import type { components, schemas } from "@/shared/protocol";

type WsEnvelope = schemas["WsEnvelope"];                 // 信封
type StateDelta = components["schemas"]["StateDelta"];    // WS 增量
type ProfileListItem = components["schemas"]["ProfileListItem"]; // HTTP 响应
```

- 联合判别靠 `channel`/`type` 字面量联合，switch 收窄，避免手写 any。

## 7. 增删协议字段的流程

1. 改 sim 端 pydantic 模型（唯一真相源）。
2. 跑 `npm run gen:protocol`，本地验证 `shared/protocol.ts` 变更符合预期。
3. 提交 `sim/api/*.py` + `shared/openapi.json` + `shared/protocol.ts`（三者同一次提交，否则 CI 漂移闸失败）。
4. 如改了 WS 消息集合，同步更新 `versioning.md` 的版本号。
