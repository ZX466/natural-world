## 2. 可行性证据（主树实测，2026-10-23）

等距化只需**两个收口点**，其余全部是既有资产的延续：

1. **投影是单一线性函数**：全代码库世界→屏幕只有 `x * TILE` / `y * TILE` 一种算式
   （WorldScene.ts:353-377 实体/影子/名牌，:228 目标标记，:256 调试层）。
   等距化 = 换成一个可逆投影函数 `isoProject(x,y)` + 逆变换 `isoUnproject(px,py)`
   （纯函数，可单测——**C5 精神在前端的延伸**）。
2. **地图渲染收敛在一个函数**：`redrawMap()` 画到离屏 canvas 再贴纹理（:152-206）——
   换成「方块三面绘制」只动这一处。
3. **深度排序已存在**：实体按 `(actor.y + 1) * TILE` 排深度（:354-358）——等距体素的
   经典按行排序就是它，天然延续。
4. **天气/昼夜是屏幕空间覆盖**（rainLayer setScrollFactor(0)、色罩）——零改动存活。
5. **点击寻路**：点击→格子命中改走 `isoUnproject`，后续 move 请求逻辑不动。

## 3. A0 技术设计

### 3.1 等距体素外观（Minecraft 风格的 2D 实现）

- **投影**：经典 2:1 等距（`sx = (x - y) * TW/2`，`sy = (x + y) * TH/2 - h * HH`），
  菱形顶面 + 左右两个侧面 = 一个"方块"
- **高度表**（**按坐标 (x,y) 查离线产物**，不是按 tileId——tileId 是整图切片序号；
  产物由 tileset 采样聚类生成，见执行规格 §3.1）：草/田/石→1、水→0（下陷）、
  树→3、墙/屋顶→2（确定性查表，零新状态）
- **面着色伪 AO**：顶面 100% / 左面 ~75% / 右面 ~60% 亮度——体素立体感的零成本实现，
  这一笔就是"致敬感"与"廉价感"的分水岭
- **方块图集**：content 管线新增 `build_block_atlas.py`（**复用 png_codec.py 零依赖**
  程序化生成 16×16 纹理 × 三面着色变体，同输入逐字节可重建——**不用 Pillow**，
  与 build_god_characters 同纪律）；**色源 = god-town tileset 采样色**（底图已换
  桃花源，sprout 调色板仅历史管线用）
- **性能**：140×100 = 1.4 万格，静态图先渲染成一张大 canvas 纹理（现 redrawMap 同款
  手法），动态重绘只在 TILE_CHANGED 后局部失效——比逐格 sprite 更省

### 3.2 实体 = billboard（17 张古风 sprite 的 100% 保留）

等距世界里立 2D sprite 是成熟手法（Eastward/Octopath/无数 MC 风 2D 游戏）：
- 站位 = 方块顶面中心 `isoProject(x, y, effectiveHeight(x,y))`（**不是 h=0**——
  地面块高 1，写 0 会陷进地里；结构格按 built/collapsing → h=2）
- 深度 = `depthKey(x,y)+1`，与高块/结构同池（(x+y) 行序，北被南遮）
- 四向行走动画、影子、名牌、气泡全部原样
- 古风村民人格外观**零重绘**延续；未来想换方块小人（MC skin）是纯表现层替换，随时可做

### 3.3 渲染器策略模式（回退保险 + 语义漂移证明）

```
renderer: 'flat' | 'iso-voxel'   // 配置切换，运行时可切
```

- `flat`（现渲染器）**不删**：任何阶段可一键切回 2D 平面
- 切换验收：同世界同帧在两种渲染下实体/事件/交互完全一致——**换皮不换魂的机器证明**
- V3 收官后才考虑 flat 退役（或永久保留作低配模式，零维护成本）

## 10. 二次推敲（自我审查 · 2026-10-23）

对 §1-§8 逐节重审，发现三个前版未暴露的真实问题与若干小项，修订如下：

### 10.1 发现一：16px 菱形在等距下视觉过小（渲染尺度裁决 R1）

等距投影把 (140,100) 地图折成菱形后，**视觉密度远高于平面**：TILE=16 的菱形格在
2:1 投影下仅 16×8 像素，方块三面总高 ~24px——比现在平面 16px 格还密，且 16×32
sprite 站上去比例失衡。**修订**：等距渲染器内部用 **ISO_T = 32**（渲染时 2× 放大），
即投影参数与逻辑 TILE=16 解耦（`isoProject(x, y) = ((x−y)·16, (x+y)·8 − h·16)`，
菱形 32×16、方块总高 ~48px——sprite 比例恰好）。逻辑层/sim/协议零影响（纯渲染常数）。

### 10.2 发现二：等距全图画布尺寸与内存（性能账重算）

平面画布 2240×1600；等距画布（含高度）≈ (140+100)×16 宽 × (140+100)×8 + 高度
≈ 3840×2100 ≈ **32MB RGBA 单纹理**——可接受但逼近手机 WebGL 上限（一般 4096×4096
安全线内）。**修订**：V1 先单画布（桌面无虞）；V3 若需移动端再切 4×4 chunk 画布。
§7 「先全图重绘」结论不变。

### 10.3 发现三：摄像机边界与镜头跟随在等距下需重算（V2 隐性工作项）

平面 `setBounds(0,0,w·TILE,h·TILE)` 在等距下是错的——世界包围盒是**菱形外接矩形**，
且实体 billboard 的屏幕 y 带高度偏移。**修订**：V2 验收清单追加「摄像机边界 =
菱形外接盒 + 边距；跟随陈默时相机中心 = `isoProject(pos) + (0, −blockTop)`」。
另：点击拾取的菱形内判定（`isoUnproject` 的 half-plane 测试）必须带单测——这是
§3.1 纯函数测试的自然延伸，不新增风险。

### 10.4 小项核对（无修订，记录结论）

- bubble/名牌/目标标记的定位：全部经 `isoProject` 适配（V3 既定项，无遗漏）
- 雨层/昼夜色罩：屏幕空间 `setScrollFactor(0)`，**确认零改动存活**
- TILE_CHANGED 局部失效：等距下失效区域 = 变更格 + 其「投影阴影区」（东南向格），
  V1 全图重绘阶段无此问题，V3 优化时注意**阴影区**这一等距特有概念
- A 级回放导出：数据层能力，与渲染器无关，不受转向影响
- V0 的 63 提交推送：GitHub 走代理 127.0.0.1:7897（workflow.txt 既定约定），
  gitee 直连——推送命令不变

### 10.5 推敲总结

三个发现全是**渲染层常数与包围盒几何**问题，无一处触及架构决策——等距路线的
「sim 零改动、协议零变更」主张经二次审查后**依然成立且更精确**。方案定稿。

## 11. 终审修正（执行前审核 · 2026-10-23，指向 voxel-execution-spec.md）

对 §1-§10 的最后一轮代码级审核，四处修正——**执行以本节 + 执行规格书为准**：

- **R4 混合分层（修正 §3.1 单画布主张的内在矛盾）**：单张全图画布 + 实体永远置顶
  会导致「实体走到树后被树冠正确遮挡」不可能实现（§10.4 已见症状但未给解法）。
  修正：**h≤1 的矮块烘进画布；h≥2 的高块（树/墙/屋）作为 Phaser 图片对象与实体
  同深度池按 `(x+y)` 行序排序**——实体在树北侧（x+y 更小）先画即被树冠遮挡，
  在南侧后画即在前。这才是 Eastward 式正确遮挡的最小实现。
- **R5 依赖事实**：`sim/content/png_codec.py` 已存在（zlib+struct 零依赖编解码，
  build_god_characters 同款）——`build_block_atlas.py` 直接复用它，不引入新依赖
  （pillow 虽在锁内但管线纪律以 png_codec 为准）；另 **V1 零纹理验证不需要 IsoBox**
  ——画布上直接画菱形三面平涂（颜色取自 **god-town tileset 采样色**，非 sprout
  调色板——底图已换桃花源）即是零纹理，比 1.4 万个 IsoBox Shape 对象更简单
  （§9.1 的 IsoBox 建议作废，被画布平涂取代）。
- **R6 拾取简化**：点击拾取只做**地平面命中**（忽略高度柱）——移动目标本来就是
  可走地面格；高块背后点选留待真需要时再做，V1-V3 不做。
- **地图尺寸实测为 140×100**（build_god_town.py:37-38 `MAP_W/MAP_H`）——画布按此计算，
  但代码仍以常量为真源（换图时同改）。
