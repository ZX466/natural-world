# 人物 3D 化：已实施形态与后续档位

> **状态：B 档已实施（2026-11-09，`2ac5ed2`）。** 本文不再是待决方案，只记录
> **做成了什么样**、**与当初 B 档估算差在哪**、以及**再往上还要什么**。
> 当初的分档与成本估算（A/B/C/D、人日、素材管线）已随实施完成归档，
> 需要考古走 `git log -- docs/arch/character-model-3d-plan.md`。

## 1. 现在是什么

`?avatar3d=1` 把**全部人形角色**换成 3D 体素模型；默认仍是已验收的 2D 图集。
开关细节见根 [`README.md`](../../README.md)「2D / 3D 人物切换」。

| 项 | 实际形态 |
|---|---|
| 网格 | 每人 **1 个 `SkinnedMesh`**，16 骨骼 |
| 图集 | **1 张 512×256** `DataTexture`，全员共享 |
| 绘制 | 2346 → **~51 draw call**（50 NPC + 主角） |
| 材质 | `MeshLambertMaterial({map, vertexColors})` + `HemisphereLight` + `DirectionalLight` |
| 动物 | `fauna_*` 无 3D 模型，仍走 billboard |
| Phaser 路径 | 不读该参数，始终 2D |

实现在 `client/src/game/render/three/avatar3d.ts`；图集 `paintTile` 每格 64×64 全填底色，
不存在 alpha-0 缝隙。

## 2. 与当初 B 档估算的差异

估算里 B 档是「主角 + 1 种村民外观、方块关节层级」，**实际做到了全员共享骨架 + 单图集**，
成本远低于 C 档估算（20–35 人日）。差异原因：真 `SkinnedMesh` + 顶点色纯色件比
「每人独立网格 + 各自材质」便宜得多，图集复用让 17 种外观变成纯数据。

**这条经验对后续档位有效**：再往上不是加网格，而是加骨骼动作与贴图分辨率。

## 3. 明确没做的

- 3D 描边：主动不做（`three-actors.ts` 的主色轮廓仍是 2D 路径的事）。
- 动画混合、布料、脸部动画、逐人独立体型。
- 动物 3D 化。
- 相机绕人物旋转时的连续体积已由真蒙皮解决，但**走路/跑/跳的姿势**仍是简化帧，
  没有 D 档那种逐动作美术。

## 4. 若要再往上

D 档（低面数骨骼模型 + glTF）仍是唯一路径，代价与当初估算一致：建模、UV/贴图、
绑骨、权重、动作制作，且不同来源骨架不保证兼容。触发条件是「古风衣袖 / 身体变形 /
更丰富动作」成为需求——目前没有。

`GLTFLoader` 与 `SkeletonUtils` 属 three 的 add-on，锁定版本 `0.180.0`，
不因建模提案升级引擎。
