# 停服后的世界补跑

启动从当前世界线恢复检查点，再装配 NPC、感知、火灾、建造、体素等确定性钩子。
补跑结束后才启动模型和实时驱动任务；关闭客户端而服务器仍运行时，原有驱动一直推进。

墙钟只在 `main._offline_wall_time()` 采样一次，允许测试注入。当前分支最新检查点的
`created_at` 是进度水位，没有本分支快照时取分支创建时间。兼容 epoch、数字文本和旧 ISO
时间；无时区 ISO 按 UTC 解释。水位在未来时补跑为零；损坏时间拒绝启动，不能猜一个时长。

`sim/world/offline.py::advance_offline` 仅接受显式 `offline_seconds`。固定 1x，继承普通/
战斗时间尺，完成或失败均恢复原倍速。现行普通 1x 为 **60 tick/真实秒**，因此停机一真实
分钟补 **3600 tick（一个游戏小时）**；战斗时间尺为 1 tick/真实秒。派单中的“一小时对应
一小时”不符合当前时间比例，本实现沿既有时钟换算，不改时钟常量。

最多补 **86400 tick**。每批按当时时间尺同时满足 4 真实秒及 240 tick 上限，并在落库后
让出执行权。普通时间尺下，30 天停机只补 1440 真实秒所对应的一游戏日；剩余时长丢弃并
记录 `offline.capped`。不足一 tick 的小数尾部向下取整，不保留跨重启的亚 tick 累加器。

事件仍经 `TickLoop.enqueue/apply` 和 `flush_world` 同事务提交，不删除或改写事件。墙钟
只落在检查点控制元数据，不进入世界状态、state_hash 或事件 payload。中间批次水位按
已处理时长推进；末批水位置为本次启动采样时刻，防止重复补跑被截断的超额部分。
空事件尾部也强制保存世界游标；同一 seq 的检查点可以更新，历史玩家档仍通过受游标
约束的快照/事件路径恢复。补跑不调用客户端 fast_forward 面，也不构造或修改玩家档。

证据：`.orca/audits/offline-progress-2026-11-01/verify.py` 可在临时 SQLite 复跑分钟重启、
事件只增、玩家档不变、两遍重放、重复启动及 30 天封顶；真实 world.db 不用于实验。
