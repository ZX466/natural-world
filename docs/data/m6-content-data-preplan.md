## 1. 判据：A3 地基分类法（最新版）

一条状态**可重建** ⟺ 它能被 `events` 从 `seq 0` 折叠出来（有事件源 + 确定性 fold）。
据此当前库里的分类（`schema.md` §13–§24 汇总）：

| 族 | 表 | 依据 |
| --- | --- | --- |
| **可重放**（6 张） | `npc_profiles` / `npc_health` / `matter_state` / `structures` / `material_balances` / `fires` | 各自有事件源 + fold（`materialize_*_replay` / `fold_fire`） |
| **无事件源**（4 张） | `npc_memories` / `knowledge` / `relationships` / `npc_power` | 只有当前值 ⇒ 事件重放**永远**重建不出 ⇒ 历史点读档靠**物化包**（§23）承载，**不是**"再建一张表" |

三条从这张表推出的判据（本稿反复用）：

1. **无事件源状态不进可重放表**（否则表里出现一列永远追不上的真相）——这是 M6-A2 刚落地
   的死亡契约的反面：死亡**有**事件源，所以它**可以**投影删 `npc_profiles` 行（`schema.md` §24）。
2. **纯运行态不入库**（A8 火势口径）：能每 tick 现抽的东西，落表就是"给未来加一张没人写的表"。
3. **派生优先于存储**：先问"能不能从 tick / 世界态纯函数算出来"，能就不入库（`sim/core/calendar.py`
   的日历派生是现成例子）。

## 2. 逐事件判定

### 2.1 `ecology.shift`（生态）——不入库

- **状态**：生态相位 / 演替进度（对应 M6 的节气/日历面，P6「近零成本，只需一条防呆」）。
- **判定**：**可重放**。若生态相位由事件驱动（`ecology.shift`），则 fold 即状态；更关键的是
  相位通常**由 tick 派生**（日历/节气已有纯函数），事件只是"记录发生过迁移"。
- **结论**：**不入库**。论证同 A8 火势：纯运行态每 tick 现抽即可，落表要付「表 + fold + 迁移 +
  fork 克隆 + 物化包五处成本」，换不回任何逐位性收益。
- **需要跨会话保留吗**：生态相位由 tick 决定 ⇒ 读档后按 tick 重算即一致 ⇒ **不需要**额外存储
  （待裁点 ④）。

### 2.2 `fauna.tick`（动物）——不入库，且不进 `entities`

- **状态**：每 tick 的动物刷新集（种类/位置/半径）。M6-P13 实测：三只异半径动物的额外配对
  占 human50 基线 **18–31%**（`m6-perf-preplan.md` §3.1 判据②）。
- **判定**：**纯运行态**。刷新规则是确定性函数（半径 + tick + 位置），不需要持久化；动物也
  没有玩家投入的治理状态（无 `entry_id` 谱系、无 R-2 指针）。
- **结论**：**不入库**；并且**不进 `WorldState.entities`**（口径理由见 §4）。
- **注意**：动物的感知成本是**半径²**（`PERCEPTION_TICK_LIMIT_MS=3.6` 的定标基）⇒ 那是性能域
  的红线口径，本稿只保证**数据面不落表 + 不污染 `entity_count`**。

### 2.3 `speech.shift`（语言阶层）——推荐事件化 + `npc_profiles` 加 2 列

- **现状事实**：语言判定是**纯函数层零状态**（`sim/agent/language.py`：识字阈值 `0.5` +
  行话可懂档位 `{"士绅","行内"}`，M2 两档占位、M3 标注"扩五档"）。今天的阶层是**常量**，
  不是 per-NPC 状态。
- **M6 要的是什么**：阶层**随世界演进**（`speech.shift` 的拟名说明是"迁移/变迁"）。于是它
  变成一个 per-NPC 的持久状态 ⇒ 必须回答"有没有事件源"。
- **判定**：
  - **发 `speech.shift` 事件**（推荐）⇒ 有事件源 + fold ⇒ **可重放** ⇒ 落
    `npc_profiles` **新列**是合规的（可重放表的投影列），且 `npc_profiles` 只有 26 列，
    加 2 列对 fork 整表克隆 / 快照的代价可忽略；语义上它与 `identity_anchor`/`lod` 同属
    "人物属性"。
  - **不发事件**（阶层按 tick 现抽或 seed 定死）⇒ 它就是**无事件源状态** ⇒ 按判据 ①
    **禁止**进 `npc_profiles`（撞我自己的判例，见 `m5-power-data-preplan.md`）⇒ 只能纯运行态
    或 seed 列。
- **为什么不新开一张表**：`npc_profiles` / `npc_health` / `npc_power` 已经是三张"每 NPC 一行"的
  表；M6 若还要开表，应该留给**真正的新事实族**（而不是给"人物属性"再加一张）。若将来阶层
  要参与效用向量（批次 C 已把权力接进 utility），派生索引更好加——但那是**派生**需求，
  等它真的出现再说（待裁点 ①）。
- **迁移**：加列也要迁移（**0015 预留**，纯 `add_column`，按 0009 判据**不需要**
  `batch_alter_table`）。草案见 §3.1。

### 2.4 `fog.reveal`（迷雾）——不入表；两条路都不落表

- **现状事实（必须先对齐）**：`sim/world/fog.py`（M3 批次 D2）头注**已经写死**："纯内存、
  **不进事件流也不进存档**——迷雾是观察者视角的投影而非世界真相"；揭示单位 = chunk（16×16），
  状态 = `frozenset[(cx, cy)]`，`reveal` 幂等、frozen 返回新实例。
- **M6 的问题**：已揭示集要不要持久化（跨会话保留 = 玩家进度，丢了就重探）。
- **判定与两条路**：
  - **路 A（维持现状，零迁移）**：保持视角面纯内存 ⇒ 不入库。代价 = 跨会话丢失已揭示集
    （重探），这是**产品取舍**，不是数据面缺陷。
  - **路 B（事件化，零迁移）**：若要跨会话保留 ⇒ **必须**事件化（`fog.reveal`，chunk 粒度、
    幂等去重：同 chunk 重复踏入不产事件）⇒ 于是它属可重放族（fold = 并集）⇒ **仍然不落表**
    （事件即真相）。体量可控：chunk 粒度 ⇒ 上限 = 地图 chunk 数（256×256 地图 = 256 条），
    可忽略；若一 tick 内多次揭示，按 tick 批量一条即可。
  - **否决「落表但不事件化」**：那就是一张无事件源的表 ⇒ 按 A3 §1.4 它该进**物化包**而不是新表，
    等于给玩家档塞一份"谁见过哪里"的**视角数据**（与 M3 头注的定性冲突）。
- **⚠️ 连带动作（待裁点 ③）**：若采路 B，`sim/world/fog.py` 的头注**必须同步改**
  （今天写着"不进事件流也不进存档"）——否则下一个读代码的人会按旧口径做，而文档与实现打架
  是本仓最贵的债。

## 3. 迁移号预留（0015 起）

### 3.1 唯一候选：`speech.shift` 的 `npc_profiles` 加 2 列（**仅在采事件化时**）

对照 0014 / 0013 体例（`docs/data/schema.md` §21/§22）：

| 列 | 类型 | 约束 | 说明 | 对齐 |
| --- | --- | --- | --- | --- |
| `speech_register` | TEXT | NOT NULL DEFAULT `''`（空串 = 未表态） | 阶层档位（如 `士绅`/`行内`/M3 五档） | `npc_profiles.identity_anchor` 同款"档位字符串" |
| `speech_updated_tick` | INTEGER | NOT NULL DEFAULT 0，CHECK ≥ 0 | 该档位的最后变更 tick（对账/回归基线） | `npc_profiles.lod` 无 tick ⇒ 这里**必须**带，否则无法定位演进点 |

- 成对不变式**不进 CHECK**（两列语义独立：register 可为空而 tick 有值），只各自带域约束——
  对照 0008 之前那条教训（`fires` 的 `ck_fires_end_pair` 是**真**成对不变式才进 CHECK；
  `snapshot_seq`/`snapshot_tick` 那对也是真成对）。**别为了"看起来严谨"硬凑 CHECK**。
- 迁移体例：纯 `add_column`，**无 batch**（0009 判据）；`downgrade` 只 drop 这两列；
  **不回填**（老档 `''` = 未表态，零行合法，与 0010「回填只做必要的」同款纪律）。
- **不占号的前提**：本稿只**预留**；若施工方最终不事件化，这两列就不该存在 ⇒ **不要先落迁移**。

## 4. soak 契约交叉：动物计数**不进** `entity_count`（明写）

- **口径事实（M5-A12 核实）**：`entity_count_start/end` = `len(loop.state.entities)`，
  即 `WorldState.entities` 字典的键数；`soak.py` **零表查询**；该字典只有 `world.create`
  插键、`move`/tick 移动只改字段 ⇒ 今天**没有删除路径**（`test_m5_soak_entity_count.py` 钉）。
- **结论（明写一句）**：**动物不进 `entities`** ⇒ `entity_count` 不受影响 ⇒ soak 的
  `end == start` 契约**继续成立**（M6-A12 派的契约改法不需要为动物让路）。
- **若动物进了 `entities` 会怎样**（所以不采）：计数会随刷新波动（3 只量级）⇒ `end == start`
  立刻红，而红的原因与性能无关 ⇒ 又一次"契约冲突伪装成性能回归"；而且 `entities` 还是
  agent 闸门的公共口径（`sim/agent/gate.py` 的 `intent.target_id in state.entities`），
  混入瞬态刷新型存在会让闸门语义变松。
- **口径分工**：动物的**性能**红线在感知层（半径²、零新通道、复用既有三通道），本稿只管
  **数据面不入表 + 不污染 `entity_count`**。
