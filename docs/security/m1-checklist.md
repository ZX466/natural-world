# M1 安全检查清单（docs/security/m1-checklist.md）

> 维护：Codex（安全/合规/风险域）· 依据：DESIGN.md v2.1（冻结基线）· 日期：2026-09-19
> 用法：每条检查项都可写成自动化测试（T1/T3 级）或 code review 检查点（CR）。M1 写码前过一遍本清单，M1 完成后逐项勾验。
> 评审：cline（依赖/配置/文档域）

## 1. api_key 处理（DESIGN §15）

| # | 检查项 | 可执行形式 | 对应设计 |
|---|---|---|---|
| K1 | api_key 仅以 Fernet 密文落 SQLite；任何代码路径不得明文写库 | T1 单测：打开 profile 表，断言所有 api_key 字段以 `gAAAA` 开头或为空；grep 检查无裸 `api_key=` SQL 拼接 | §15 密钥安全 |
| K2 | Fernet 主密钥来源：优先环境变量 `LZ_MASTER_KEY`（32 字节 url-safe base64）；缺失时拒绝启动并给结构化报错，**禁止静默生成后写盘** | T1 单测：无环境变量启动 → 启动失败且报错信息不含密钥内容；CR：搜索 `Fernet.generate_key()` 只允许出现在密钥初始化 CLI，不允许出现在服务启动路径 | §15 + 补强 |
| K3 | 解密后的明文 api_key 在进程内生命周期最小化：仅 LLM client 发请求时解密，用完即丢，不进任何全局缓存/单例字段 | CR：LLM client 代码审查「明文只存在于函数局部变量」；T1：`gc` 抽查不可行则用 CR 兜底 | §15 + 补强 |
| K4 | api_key 永不进：日志（structlog 任意级别）、异常消息、堆栈、prompt、世界事件日志、WS 消息、前端 | T1 单测：构造一次故意失败的 LLM 调用，断言落盘日志全文不含 key 明文/前后 4 字符；T3：给 profile 塞哨兵值 `SENTINEL-KEY-123`，跑完整决策循环，grep 全部日志与 WS 帧 | §19 禁止事项 |
| K5 | 前端只持有 profile id；设置页回显时 key 永远显示为掩码（如 `sk-***last4`），永远不回传明文 | T1：WS/API 契约测试断言 profile 序列化字段白名单 = {id, name, base_url, model, temperature, max_tokens}，**无 api_key 字段**；CR：pydantic 模型 api_key 字段必须 `exclude=True` 或单独 Response 模型 | §15 |
| K6 | 连接测试（设置页按钮）走后端代理，前端不直接持 key 调供应商 | CR：前端 net 层 grep 无供应商域名 | §15 |
| K7 | base_url 允许用户自定义 → 必须校验 scheme（仅 https，本地 http://127.0.0.1 例外）并做 SSRF 防护：拒绝解析到内网/链路本地地址的域名（除显式本机回环） | T3 对抗样本：`http://169.254.169.254/`、`http://localhost:6379`、`file://`、重定向到内网 → 全部拒绝 | §15 + 补强（v2.1 未提 SSRF） |
| K8 | 日志脱敏中间件：structlog processor 级别对 `api_key`、`authorization`、`token`、`secret` 键值做 `***` 替换（键名不区分大小写、含嵌套 dict） | T1 单测：喂含嵌套 key 的日志 dict → 输出无明文 | 补强 |

## 2. 出戏防护（铁律 1–7 可执行断言，DESIGN §8/§19/§10）

| # | 检查项 | 可执行形式 | 对应设计 |
|---|---|---|---|
| M1-A | 禁词表（硬词）：`AI` `模型` `模拟` `游戏` `角色扮演` `tick` `entity_id` `玩家` `运气` `luck` `seed` `随机数` `重开` `重来一次` `存档` `读档` `profile` `prompt` `token` | prompt 装配函数出口处统一扫描；命中即拒发并结构化报错 | 铁律 1 / §19 |
| M1-B | 禁词扫描覆盖三处输入：① 身份锚前缀 ② 感知帧叙事化文本 ③ 记忆检索内容 + 玩家念头注入文本 | T1：构造含禁词的记忆/念头 → 断言 prompt 装配拒绝；CR：扫描函数在 prompt 组装唯一出口被调用 | 铁律 1 + §10 |
| M1-C | 玩家念头注入文本是用户输入，必须先经与 NPC 话语相同的叙事化转译管线，不得把原始输入拼进 prompt | T1：注入「你是AI吗」→ prompt 中只有转译后的念头表述，原始文本不出现 | §10 + 铁律 1 |
| M1-D | LLM 输出 reason 字段扫描：出现禁词 → 闸门拒收该 Intent，触发重规划（不是静默替换） | T3 对抗样本：fixture 中埋含「作为AI」的 reason → 断言 gate 返回结构化拒绝 | §6 Intent / §19 |
| M1-E | 独白只来自 reason 复用（零额外调用），reason 中的自我怀疑必须是「我干嘛要干这个」类第一人称内归因；出现「被指使/谁让我/外来声音」→ 违规，进 T4 出戏探针 | T4 nightly 探针 + T3 fixture：reason 含「谁在指使我」→ 拒收 | §10 抱怨合规 |
| M1-F | 第三人称自我描述探测（铁律 2）：reason/独白出现「陈默（指自己）/他（指自己）/那个叫X的人（指自己）」→ 出戏信号 | T4 探针（启发式：reason 含自身名字且动词为自我指涉）+ 人工抽查 | 铁律 2 |
| M1-G | 无存档意识（铁律 5）：感知帧/记忆/念头永远不含「分支/abandoned/重放/快照」等持久化词汇；这些词只存在于戏外调试覆盖层 | T1：全量感知帧文本 grep 持久化词汇 → 零命中 | 铁律 5 / §12 |
| M1-H | 内感受叙事化（v2.1 提前到 M1）：身体状态进 prompt 前必须经叙事化（「胃里烧得慌」而非 `hunger:72`）；数值只允许以第一人称感受语言出现 | T1：感知帧 channel=interoception 的 content 字段 grep 数字+字段名模式 → 零命中 | 铁律 7 / §7 |
| M1-I | 元信息词汇同时不得出现在戏内 UI（玩家观察视图与 Agent 感官同源同规） | T1：前端渲染文本走同一叙事化产物，CR：前端不得直接消费 WorldEvent payload | C3 双层铁律 |

## 3. LLM 输出边界（DESIGN §6/§8/§19）

| # | 检查项 | 可执行形式 | 对应设计 |
|---|---|---|---|
| O1 | Intent 是 LLM 影响世界的唯一出口：LLM 响应解析产物只能是 Intent 对象，其他字段（工具调用、自由文本指令）一律丢弃并记开发日志 | T1：喂畸形 LLM 输出 → world 状态不变 | C1 / T1 幻觉隔离 |
| O2 | Intent schema 严格校验：action 枚举外值 / target_id 不存在 / 超距 / 负金额 / 天文数字 / params 超大嵌套 → 闸门结构化拒绝（返回失败原因供重规划，不静默丢弃） | T3 对抗样本全套（§16 已列），M1 落地时逐条补 fixture | §16 T3 |
| O3 | reason 必须第一人称世界内语言：禁词扫描（M1-D）+ 长度上限（防用 reason 夹带大量文本攻击 token 预算，上限建议 500 字符） | T3：超长 reason fixture → 拒收 | §6 / §19 |
| O4 | 原始思维链/原始输出只进开发日志（structlog dev channel），不进：世界事件日志、记忆、独白、前端 | T1：跑一次决策 → 断言事件日志无 LLM 原文；CR：monologue 只取 reason | §19「不要直接渲染 LLM 原始输出」 |
| O5 | LLM 输出不可信：供应商返回内容永远当作不可信输入处理——不 eval、不模板注入（不把 LLM 文本喂回 f-string 拼 SQL/shell/路径） | CR 安全审查项 + T3：LLM 输出含 `{{}}`/SQL 片段 → 无副作用 | 补强 |
| O6 | confidence < 0.5 触发重规划：重规划次数上限（建议 3 次）后降级为 wait Intent，防 LLM 死循环烧钱 | T1：mock 永远返回低置信 → 断言 3 次后 wait | §6 + 成本治理 §15 |

## 4. WS 接口（DESIGN §3/§6/C3）

| # | 检查项 | 可执行形式 | 对应设计 |
|---|---|---|---|
| W1 | 玩家可见字段白名单：WS 推送的每条消息走白名单序列化（叙事化文本 + 表现层所需动画/弹幕状态），tick/seed/entity 内部 id/关系数值/运气/偏差参数一律不出现在戏内通道 | T1：契约测试——录制 10 分钟 WS 帧做快照断言，grep 禁词与数值字段 | C3 / §19 |
| W2 | 戏外调试覆盖层（tick 显示、全知视图）走独立 WS 通道或消息 kind 前缀，默认关闭；开关只影响戏外通道，不改变戏内通道内容 | T1：覆盖层关 → 戏内帧无差异；开 → 只有 overlay kind 帧出现 | C3 推论 |
| W3 | 任何戏外字段不得回流进 Agent prompt 或世界事件日志（调试覆盖层打开期间产生的数据同样隔离） | T1：开着覆盖层跑 100 tick → 事件日志 grep 元信息 → 零命中 | C3 |
| W4 | 玩家念头注入文本长度上限（建议 200 字符）+ 服务端（非前端）校验，防 token 预算攻击 | T3：超长念头 → 拒绝并提示 | §10 + 成本 |
| W5 | WS 消息不做「玩家→Agent 指令」直通：注入文本永远走叙事化转译（同 M1-C），绝不出现「命令语气直达 Intent」的旁路 | T1：注入「attack 小满」→ 只产生念头感知帧，不直接产生 attack Intent | §10 玩家是直觉不是指挥官 |

## 5. 通用（闸门/事件溯源/依赖）

| # | 检查项 | 可执行形式 | 对应设计 |
|---|---|---|---|
| G1 | 事件溯源 append-only：SQLite 打开只追加模式或触发器禁 UPDATE/DELETE 于 events 表；读档分叉只 INSERT 新分支 | T1 历史不可销毁不变量（§16 已有）+ T2 回放 | C4/C6 |
