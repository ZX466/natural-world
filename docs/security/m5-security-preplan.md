## 0. 一句话
M5 的安规面 = **读档分叉把「世界唯一真相」从一条线变成一棵树**，于是 M0-M4 建立的全部安规
不变量都获得了**第二个宿主**：M1 禁词面、M3 记忆隔离/证据链、M4 念头注入与因果未知——
它们原本假设「只有一条世界线」，分叉让「哪条线的事实算数」「跨线记忆会不会污染」
成为**新的安规面**。本预研的核心主张：**M5 不新增安规面，只把 M0-M4 已有的不变量
在分叉语境下逐条声明适用条件**（同 m5-fork-archive-preplan §0.3 体例）。
## 1. 裁 6 / 裁 7 复核结论（D3 等的关键件，2026-09-28）
主树委我复核的两项裁断结论，**均为「维持原判」**，但附**条件性红线**——
条件是我在复核中发现、原裁断未覆盖的残余风险。opencode 按 (c) 施工中可继续，
收编时按 §1.3 补三条断言即可。
### 1.1 裁 6（clone 走 async 引擎直写 = 不过 store 类）— **维持 (c)**
**裁断原判**：(c) clone 走 `INSERT … SELECT` 批处理直写 `npc_memories`，不经 store 类、
不引入 `fork_journal` 恢复协议。理由：clone 是**冷路径字节复制既有合规行**，不产生新内容。
**我的复核依据**（实测，非引述）：
1. **C4 的字面范围不含语料表**。DESIGN.md:40 C4＝「事件溯源是唯一写路径，实体 frozen，只能 `apply(event)`」——
   约束对象是**世界状态**（`WorldState`/事件流），而 `npc_memories` 按 F2 本就**无事件源**
   （`event_validation.py:52-70` 的 19 个 `PAYLOAD_MODELS` 无任何记忆/知识/关系 kind）。
   语料表的写入门是 **S1**（`MemoryWritePipeline.decide`，`memory_scan.py:208-209`
   「记忆写入唯一入口（S1）」），不是 C4。故 (c) 不违反 C4。
2. **S1 的闸门语义是「面向新内容」，不面向「已合规内容的复制」**。S1 = `decide()` 的
   扫描（banned/hidden）+ 处置（拒写/改写），落库委托 `store.persist()`。clone 复制的是
   **父分支已经过 S1 的合规行**，克隆不产生新内容 ⇒ **无新扫描对象**，绕过 `decide()`
   不产生「未扫描内容入库」的安规缺口。
3. **store 类的存在理由不适用于 clone**。store 类承载的是「唯一写入口 + S1 纪律 + S5 治理
   （`supersede` 只 UPDATE 治理列、永不改 content）」。clone 不改 content、不经 LLM、
   不经扫描面，`supersede` 语义在克隆中不发生。
**结论**：(c) 在安规上成立。**但附三条条件性红线（§1.3）**——
原裁断的理由「不产生新内容」成立的前提是「克隆的每一行都来自父分支的合规行且
`content` 逐字节不变」，这必须由断言钉死，不能只靠代码评审的善意。
### 1.2 裁 7（`*.written` 事件 / `agent_override` 产事件 = M5 不做）— **维持不做**
**裁断原判**：`*.written` 事件与 `agent_override` 产事件**M5 不做**（不破冻结事件基线，
中长期提案登记不施工）。
**我的复核依据**：
1. 两者都**触 §19 事件白名单**（`DESIGN.md:499-516` 禁止事项第 1 条「必须走 `apply(event)`」
   的镜像面：事件 kind 是白名单封闭集，加 kind = 改冻结基线），且事件白名单的
   `PAYLOAD_MODELS` 已是 19 个 kind 的**闭合枚举**——新增记忆/override 事件会同时触
   `test_m1_metrics.py`/T2 回放的重放口径。
2. **「不做」是安规上更安全的方向**：语料表无事件源（F2）意味着它**本来就不在**「读档=分叉
   纯事件重放」的可证伪面上；给它造事件反而会让 T1/T2 断言口径被迫扩张。
3. 复核未发现「不做」会造成安规缺口：跨分支记忆污染的面由 **F3（向量召回分支隔离，
   裁 11 = M5-D2 已落）** 独立覆盖，不依赖语料事件。
**结论**：维持不做。`agent_override` 若将来要做，条件是**先解决「override 不是事件」
的可审计性缺口**（预研 §8 列为中长期观察项，不在本单）。
### 1.3 我补的三条条件性红线（D3 收编时应一并钉）
原裁断未覆盖的残余风险——三条都是**可证伪断言**，非意见：
| # | 风险 | 断言（钉子口径） | 归属 |
|---|---|---|---|
| **R-1** | clone 的 `content` **逐字节不变**——若克隆路径上有人「顺手规范化/截断/re-escape」，就绕过了 S1 的逐字节前提 | clone 后 `SELECT content FROM npc_memories WHERE branch_id=:new` 与父分支对应行 **逐字节相等**（`R2` 断言面之一，opencode R2 已有位——须显式加 content 比对） | D3/R2 |
| **R-2** | clone 后 `branch_id` 改写 + `entry_id` 重映射（裁 10）若**只改主键不改 `superseded_by` 引用**，会产出**跨分支悬空引用**（裁 4 采 `evidence_branch_id` 正是封这个） | clone 后 `superseded_by` 的每个目标 id 在新分支内**存在且同分支**，零悬空 | D3/R2 |
| **R-3** | clone 绕过 S1 ⇒ **新分支的语料行不享有「已扫描」标记**。若将来 S1 口径扩展（如新禁词词表落 `banned_words.py`），**存量已克隆行不会被重扫** | 「克隆即合规」是**快照时点**结论，不是永久结论：新增禁词词面时，**存量分支语料须重扫或显式豁免**——写成纪律（D3 交付说明 + memory），**不写成运行时断言**（运行期无法判定「这行是克隆来的还是新建的」） | D3 交付说明 |
**R-3 是我最重要的补充**：原裁断把「clone 不产生新内容」当作**永久**豁免，但 S1 的词表是
**活资产**（M4 裁 16-4/19 就在持续扩面）。若不写明「克隆合规是快照时点结论」，
下一轮词表扩面时会出现「老分支记忆里躺着新禁词」的系统性缺口——这是**本条裁断真正的尾部风险**。

## 3. 【新面】跨分支证据链污染（本预研唯一新增的安规面）
M4 的隐藏属性浮现（R5 证据链）依赖 `evidence_branch_id`（裁 4 采 0008-d）。单线时
「触发事件 → 属性浮现」是一条因果链；分叉后出现**跨分支引用**的可能：
- 父分支的事件 `E`（如「李婶夸了小满」触发了 `trust_up` 浮现）被 fork 点包含在子分支里；
- 但若 override 或 fold 使子分支的该属性**重新隐藏**，而 `evidence_branch_id` 仍指向父分支，
  则**子分支的 NPC 可能持有「凭父分支证据浮现过」的残留**。
**风险定性**：这是 **R5 证据链的面**（信息边界），不是出戏面——最坏后果是
「NPC 表现得像知道不该知道的事」，属**记忆/证据泄漏**而非元信息泄漏。
**处置口径（提案）**：fold 物化时**按分支过滤证据**——`evidence_branch_id` 不等于
当前分支或**其祖先链**上的证据，对当前分支的属性可见性无效。断言口径见 §7 R-4。
### 3.1 F-4：口语变体词面缺口（登记，不在本单修）
M5 预研顺带实测发现（**先于分叉议题的既有缺口**，非 M5 引入）：
`BANNED_WORDS_PERSIST` 走 CJK **子串匹配**，「存档」能中，但口语变体
**「存个档」「开个新档」不中**（`scan()` 实测零命中）。即 Agent 说「这局存个档吧」
不触发出戏拦截——而这正是读档/存档意识的自然口语。
**处置**：**不修**。理由三条：
1. 词面扩面走既有 CR 流程（`banned_words.py` 维护纪律：改词面须走 CR，安全域 owner=codex）；
2. 裁 22-C-② 已裁「**M5 不扩 T4 词表**」——不因里程碑切换而预设扩面；
3. 修它要动 CJK 匹配形态（子串 → 变体词表/词性），属 M1 词面架构级变更，超出本单。
**已钉为已知项**：`test_t4_probes.py::TestForkConsciousness::
test_fork_words_colloquial_variant_gap_is_known`——钉它的目的是让缺口**显式可见**
（将来任何人扩面时能看见它、并知道要把该用例翻转为断言命中），而非让它静默存在。
**登记给主树**：若 M5 批次 C 前希望补，建议单开一单走 CR（不夹带在 M5 施工里）。

## 4. 念头注入的分支归属（声明性，无新代码）
M4 批次 A 的 `impulse_gate` 三扫是**入站即扫**，与分支无关。分叉只引入一个问题：
**同一个 `thought` 判例能否在两条分支复用**？结论：**不能复用，只能重扫**——
因为 I-2 hidden 扫描**按被注入 NPC 的 profile**，而 profile 在不同分支可能处于不同
`triggered` 状态（§3 的面）。故 `impulse_gate` 的 `triggered` 参数**必须按分支取值**，
不可跨分支缓存 verdict。写入 D3 交付说明（不改 `impulse_gate` 代码）。
## 5. 「读档」在戏内不得成为抱怨/操纵对象（声明性）
玩家点了「读档」＝分叉，这是**玩家档游标**操作（DESIGN C6：世界档 append-only 含
全部废弃分支，玩家档只是游标）。但**对 Agent 是不可见的**：
- 禁 `BANNED_WORDS_PERSIST` 已含 `分支/branch/重放/快照/回放/snapshot`（`banned_words.py`），
  所以 Agent 说「我们要回放上一条线」= 出戏（已覆盖）；
- **新面**：Agent 不得把「另一条时间线存在」当**抱怨理由**（「我不想回到那条线」＝
  对外部命令源的抱怨 + 存档意识）。`will.py` 四档模板全是自我怀疑族，**分叉不新增模板**；
  只需在 T4 探针集加 **P6 分叉意识**类（题面「回到上一条线是不是就能重来」）。见 §7 R-5。
