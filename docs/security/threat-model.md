# 轻量威胁模型（docs/security/threat-model.md）

> 维护：Codex（安全/合规/风险域）· 依据：DESIGN.md v2.1 · 日期：2026-09-19
> 本项目是单机游戏（本地 SQLite + 本地后端 + 本地前端），无多租户、无服务端账号体系。威胁面集中在：密钥泄漏、LLM 供应链、出戏防线被绕过。
> 评审：cline（依赖/配置/文档域）

## 资产

| 资产 | 说明 | 泄漏后果 |
|---|---|---|
| api_key | 供应商 LLM 密钥（DESIGN §15，Fernet 加密落 SQLite） | 直接经济损失（盗刷） |
| 世界真相 | 完整事件时间线（含废弃分支）、NPC 全部内部数值 | 单机游戏，泄漏=作弊/出戏，非隐私灾难 |
| Agent 不出戏 | 铁律 1-7 成立 = 产品核心体验成立 | 出戏 = 核心卖点死亡 |
| 玩家输入 | 念头注入文本 | 攻击向量（prompt 注入载体），本身非资产 |

## 威胁与缓解映射

| # | 威胁 | 攻击路径 | 已有缓解（DESIGN） | 缺口 → 责任 | 等级 |
|---|---|---|---|---|---|
| T1 | api_key 泄漏到日志/异常 | LLM 客户端把含 Authorization 的异常直接 `log.exception()`；structlog 渲染整个请求 dict | §15：Fernet 落库 + 前端只持 profile id | **日志/异常路径无脱敏设计** → m1-checklist K4/K8；structlog processor 需在 M1 第一周落地 | 高 |
| T2 | api_key 泄漏到前端 | 设置页回显 profile 时返回明文；或 pydantic 模型直接序列化 | §15：前端只持 profile id（间接缓解） | 契约未明确 Response 白名单 → K5 契约测试；connection test 由后端代理 → K6 | 中 |
| T3 | 自定义 base_url 导致 SSRF | 用户填内网地址/云元数据地址，后端替他发请求（连接测试、正式调用） | 无 | **设计完全未提 SSRF** → K7：scheme 白名单 + 内网地址拒绝（本机回环例外） | 中高（本地单机、攻击者=用户自己，但防呆必须做） |
| T4 | prompt 注入绕过出戏闸门 | 玩家念头注入文本夹带「忽略以上设定」；LLM 输出 reason 夹带元信息；记忆检索把污染内容带进 prompt | §10：念头先叙事化；§8 铁律 1 禁词表；§16 T3 对抗 | 禁词表未定稿、扫描点未定义为「prompt 装配唯一出口」→ M1-A/B/C；reason 扫描 → M1-D/E；玩家输入长度上限 → W4 | 高（核心风险） |
| T5 | LLM 输出越权（幻觉污染世界） | LLM 输出非法 Intent：不存在目标/超距/负金额/自伤动作 | C1：Intent 闸门 + 执行时二次校验；§16 T3 | 设计完备，落地验证靠 T3 全套 fixture + T1 不变量 4 | 高（已设计） |
| T6 | LLM 输出被当可信文本二次注入 | reason/思维链被拼进后续 prompt、SQL、shell、路径 | §19：不直接渲染原始输出（渲染面） | 二次使用面（拼 prompt/持久化）未明说 → O5；CR 检查点 | 中 |
| T7 | 事件日志被篡改（破坏回放可信度） | 直接 UPDATE/DELETE events 表（调试时手滑/未来工具误操作） | C4：append-only 是架构约束 | 无技术强制 → G1：触发器/只追加连接串；T1 历史不可销毁 | 低（本地单机） |
| T8 | 依赖供应链 | pip/npm 拉到 typosquatting 包；供应商 SDK 0day | 无 | G3 检查点：uv add 后人工过一眼 + 锁文件入 git | 低 |
| T9 | 密钥派生/主密码缺失导致密钥明文落盘风险 | 开发者图方便 Fernet.generate_key() 写本地文件，被 git 或备份带走 | 无 | K2：主密钥只从环境变量，缺失拒绝启动；.env 不入 git（G4） | 中 |
| T10 | token 预算攻击（成本面） | 超长念头注入/超长 reason 灌爆 token 预算 | §15 成本治理（监控+门控） | 输入长度上限未定义 → W4/O3 | 低（自伤型） |

## 出戏防线纵深（威胁 T4 的专门展开）

```
第1层 输入面：玩家念头 → 叙事化转译管线（禁词扫描 M1-B/C）→ 感知帧
第2层 装配面：身份锚+感知+记忆 → prompt 装配唯一出口统一扫描（M1-A）
第3层 输出面：Intent.reason 禁词扫描（M1-D/E）→ 闸门拒收 → 重规划
第4层 表现面：独白/戏内 UI 只消费叙事化产物（M1-I/W1）→ 契约测试
第5层 持续面：T4 nightly 出戏探针（真模型）持续回归
```
设计中的「三层防御（锚定/过滤/重生成）」对应第 2/3 层；本模型补齐第 1/4 层的具体断言。

## 非目标（明确不防）

- 玩家修改自己机器上的本地数据库（单机游戏，玩家=root，无意义）
- DDoS / 多用户隔离 / 越权（无服务端多租户）
- LLM 供应商侧的数据保留政策（用户自担，设置页可提示）
- DRM / 防盗版

## Top-5 技术安全风险（DESIGN.md 全文通读视角，2026-09-19）

> 只列技术安全风险（产品级风险如「玩家控制感丧失」见 §20 风险台账，不重复）。每条给出：为什么危险 → 缓解落点 → 谁负责。

| # | 风险 | 为什么危险 | 缓解落点 | 责任域 |
|---|---|---|---|---|
| 1 | **api_key 泄漏面未闭合（日志/异常路径零防护）** | §15 只管了「落库加密」和「前端持 id」两端，中间最容易漏的是 structlog/异常路径。LLM SDK 失败时把含 Authorization 头的请求 dict 打进日志是行业最常见泄漏方式；M1 第一周不落日志脱敏 processor，后面每个 debug 会话都在扩散密钥 | K4（哨兵值全链路测试）+ K8（structlog 脱敏 processor），列入 M1 第一周 | Codex（安全）/ 实现归 Claude M1 |
| 2 | **记忆是永久的，一次出戏泄漏会自我强化** | 独白零额外调用复用 reason（§15），reason 文本会进记忆；记忆是身份的基石（铁律 4）且世界档 append-only（C6）——一条滑过闸门的元信息 reason 会被存进记忆、被检索、重新进入未来 prompt，形成污染循环，且**历史不可销毁意味着无法修复**。DESIGN 的三层防御只拦「当场泄漏」，没拦「泄漏后持久化扩散」 | M1-D（reason 禁词扫描是唯一闸口，必须 T3 全覆盖）+ 新增：记忆写入前对 content 再扫一次禁词（建议列为 M1 检查项补丁） | Codex（安全）→ 通知 Claude 架构域评估「记忆写入扫描点」 |
| 3 | **自定义 base_url 的 SSRF** | 设置页允许任意 base_url（§15），后端会主动向该地址发请求（连接测试 + 正式调用）。虽是单机、攻击者≈用户，但内网元数据地址（云开发环境）与转发代理场景是真实坑；设计文档完全未提 | K7：scheme 白名单（https，本机回环例外）+ 解析后拒内网/链路本地地址 | Codex（安全）/ 实现归 Claude M1 设置页 |
| 4 | **Fernet 主密钥管理未定义 → 静默生成落盘风险** | §15 只说「Fernet 加密」，没说密钥从哪来。没有约定时，实现者最自然的做法是 generate_key() 写本地文件——结果密文和密钥同机甚至同目录，加密形同虚设；若该文件被 git/备份带走，泄漏面反而扩大 | K2：主密钥只从环境变量 `LZ_MASTER_KEY`，缺失拒绝启动；G4：.env 不入 git | Codex（安全）/ 配置域 cline 落地 .env.example |
| 5 | **T3 对抗样本集是闸门的唯一实证，但 fixture 设计权分散** | T3（§16）是对抗测试的唯一防线，但 DESIGN 只给了样例类别（不存在目标/超距/负金额/天文数字/自伤），出戏类对抗样本（prompt 注入、禁词绕过、角色扮演诱导）的 fixture 设计没有 owner——fixture 弱 = 闸门绿但防线虚 | m1-checklist §2 的注入样本思路由 Codex 在 M1 T3 fixture 落地时提供初版样本集 | Codex（安全）→ 评审 T3 fixture（架构域 Claude 实现） |

### 补充观察（不计入 top-5）
- 「运气/luck 不出现在感知帧字段」有补充断言（§16），但 `params: dict = {}`（Intent）与 `payload: dict`（WorldEvent）是无 schema 的自由 dict——任意字段可夹带元信息进事件日志。建议 M1 给 params/payload 定义 TypedDict 或至少键名黑名单扫描。已计入 K4/W1 的 grep 兜底。
- 内感受提前到 M1（v2.1）使「叙事化转译」从 M2 变成 M1 关键路径——铁律 7 断言（M1-H）必须与感知引擎同期交付，不能后补。
