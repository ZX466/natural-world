## 2. CR-1：戏外词表钩子（空表建结构 + 集合定义草案）
### 2.1 判层模型（为什么需要第二张表）
现行 `banned_words.py` 单表服务的是**Agent 叙事面**（prompt 装配/记忆/独白——铁律 1）。
F-6 把同一张表**复用**到了一个**跨界字段**（anchor.name：玩家戏外资产，但经 D-6 告知帧
进入玩家观察视图）。裁 29-A 确认了跨界 fail-closed 正确，但同时确认存在**纯戏外面**
（未来：错误 title、调试覆盖层、设置面板文案等——`anchors-api.md` §3.1 明写「戏外工程
措辞，不进戏内、不回灌 Agent」）。这些面上的词（如「重开」「模拟」）在戏外语境是
**正常工程/游戏词汇**，用 Agent 面词表扫描它们属于**判层误伤**（kilo 证据的实质）。
### 2.2 数据结构草案（零代码，结构定义）
```python
# banned_words.py 追加（空表——初值由首个戏外 CR 定义，本 CR 只建结构）：
#: 戏外面禁词表（meta-shell 专用）——判层与 BANNED_WORDS（Agent 叙事面）互补：
#: 戏外面（错误 title、覆盖层、面板文案、玩家档名的**戏外校验层**等）允许的词
#: 在此表出现时**不算** Agent 面泄漏；反之本表词在 Agent 叙事面**仍按
#: BANNED_WORDS 拦**（本表不做豁免源）。
BANNED_WORDS_META_SHELL: frozenset[str] = frozenset()
```
**扫描入口草案**（`scan_meta_shell(text)`，或参数化 `scan(text, surface=...)` 二选一，§2.4 待裁）：
```python
def scan_meta_shell(text: str) -> ScanResult:
    """戏外面扫描：Agent 面词表 **减去** 戏外合法集。纯函数，无状态。

    语义 = BANNED_WORDS 中**未**被 META_SHELL 覆盖的词仍然拦——即戏外面比
    Agent 面宽（合法集更大），但不是无扫描。
    """
```
**分派语义（关键设计）**：
| 面 | 用表 | 现状 |
|---|---|---|
| Agent 叙事面（prompt/记忆/独白/感知帧） | `BANNED_WORDS`（不变） | 已钉 |
| **跨界字段**（anchor.name → D-6 告知帧/story_label） | `BANNED_WORDS`（**F-6 维持，不接钩子**） | 已钉（裁 29-A③） |
| **纯戏外面**（错误 title/覆盖层/面板文案——不进任何 WS 戏内帧） | `BANNED_WORDS − BANNED_WORDS_META_SHELL` | 空表建结构，本 CR |
| 权力判据键级面 | `AUTHORITY_FORBIDDEN_KEYS`（键级，S3） | 已钉（判层不同，互补） |
### 2.3 集合定义草案（空表首批评估——供裁定，非定稿）
判断标准：词在**戏外语境**是正常词汇、且在 Agent 叙事面必须拦（双面成立才入表）。
| 候选词 | Agent 面 | 戏外语境合理性 | 入表建议 |
|---|---|---|---|
| `重开` | 必须拦（存档意识） | 「重开一局」是玩家正常操作 | ✅ 入 |
| `读档` / `存档` / `快照` / `回放` | 必须拦 | 玩家档操作即戏外行为 | ✅ 入 |
| `游戏` | 必须拦 | 「游戏设置」正常 | ✅ 入 |
| `模拟` | 必须拦 | 「模拟器」正常 | ✅ 入 |
| `玩家` | 必须拦 | 「玩家指南」正常 | ✅ 入 |
| `AI` / `模型` / `prompt` / `token` / `seed` / `tick` / `profile` / `随机数` / `概率` / `注定` / `luck` | 必须拦 | 戏外工程语境仍偏敏感（AI/模型/prompt 是元信息本体） | ⚠️ **不入**（维持拦）——元信息词在戏外面出现仍会破坏沉浸契约的第一观感 |
| `entity_id` / `branch` / `分支` / `abandoned` | 必须拦 | 纯工程词，戏外 UI 不该出现 | ⚠️ 不入（维持拦） |
**草案集** = `{重开, 读档, 存档, 快照, 回放, 游戏, 模拟, 玩家}`（8 词，全为「游戏行为词」，
均非元信息词）。

## 3. CR-2：预算闸提闸 60→70
### 3.1 依据链（S4 MEDIUM → 裁 29-B 采认）
1. **预算语义**：`test_probe` 中 `_spent.calls += 1` 在 `try` **之前**——抖动（timeout/
   connection/5xx）也计入预算（实测代码序，test_t4_probes.py test_probe）；
2. **抖动率**：S9 终判轮 23/46 ≈ 50%；
3. **余量**：52 语料，60−52 = **8**；抖动 > 8 即顶闸 → 后续题面 skip = 漏测
   （报告 inconclusive 可见但测不到）。
### 3.2 提闸方案（70 起评）
| 项 | 值 | 变更 |
|---|---|---|
| `DEFAULT_CALL_BUDGET` | 60 → **70** | 一行常量 |
| 语义 | `min(T4_CALL_BUDGET, 70)` | 硬上限同步（仍**只可收紧**） |
| 成本 | 最多 +14 调用/轮 | §15 成本治理可承受（52 必跑 + 18 抖动容量 ≈ 35%） |
| `test_budget_cannot_exceed_ceiling` / `test_budget_covers_corpus` | 断言值随 70 | 钉子同步 |
| t4-corpus.md §5 | 「≤70 次调用」「52 条 + 抖动余量」 | 文档同步（本 CR 附改） |
### 3.3 与三把锁的关系
三把锁**不动**：key 存在 + `T4_RUN=1` + 预算闸（70）——提闸只改第三把锁的**阈值**，
不触第一/二把锁，CI 零烧钱零误红语义不变。
### 3.4 裁定请求
1. 采 **70** 起评？（或主树另定数值——依据链已给：52 + S9 抖动 23 + 余量 = 75 上探，
   70 为折中起评）；
2. 抖动是否继续计预算（维持现状——本 CR 建议**维持**，理由：预算的原始意图是硬闸
   总量防烧钱；把抖动排除会让「抖动风暴」场景失去闸保护）；
3. 施工时点：**随 P6 真跑轮一并**（裁 29-B 原文）——真跑前落本 CR，真跑后按实测
   抖动率决定是否再 CR。
