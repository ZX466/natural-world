## 0. 一句话 + 实施件三件
T4 = 「锁定模型版本下，测**过滤 + 重生成后的最终输出**有多少泄漏」。所以输入侧题面可复用
t3-corpus 语料，**断言点在输出，不在输入**。
| 件 | 路径 | 性质 |
|---|---|---|
| 语料真相源 | `docs/security/t4-corpus.md`（本文件） | 唯一真相源，改语料先改这里 |
| 机器可读 fixture | `sim/tests/fixtures/t4_corpus.py` | frozen dataclass，承 `t3_corpus.py` 风格 |
| 探针测试 | `sim/tests/test_t4_probes.py` | 语料门禁（无 marker，随 CI 跑）+ 真模型探针（`t4` marker，默认 skip） |
接线（`t4-nightly.yml` 探针 step / 锁版本 env）归 cline 域（m4-security-preplan §6.3），本单只交实施件。
## 1. 使用方式（运行与防误烧钱）
### 1.1 双纪律
- **文件路径**：`sim/tests/test_t4_probes.py`（CI 里 T3 门禁同款做法——按路径选，按 marker 选会收 0 用例）；
- **`t4` marker**：真模型用例一律 `@pytest.mark.t4`，**不进 `ci.yml`**（§16：烧钱 + 抖动）。
### 1.2 运行
```
# 无 key 环境（CI / 日常）：全部真模型用例 skip，语料门禁照跑
uv run pytest -m "not bench"

# 真模型探针一轮（本地，需显式开启 + 运行时 key）
$env:T4_MODEL_API_KEY = "<运行时给，不落盘>"   # 或 $env:T4_MODEL_API_KEY 已有
$env:T4_RUN = "1"                              # 显式选择开关（缺省 0）
uv run pytest sim/tests/test_t4_probes.py -m t4 -v
```
### 1.3 env 三件套
| 变量 | 缺省 | 说明 |
|---|---|---|
| `T4_MODEL` | `Deepseek-v4-flash` | §5 锁版本防静默回归 |
| `T4_MODEL_API_KEY` | **无缺省** | 缺 → 模块级 skip；**永不写进任何文件/文档/yml，只运行时环境变量** |
| `T4_MODEL_BASE_URL` | `https://chatapi.weixin.qq.com/openai/v1` | OpenAI 兼容端点；该端点国内直连，**不走 7897 代理**（7897 仅 github.com 域） |
### 1.4 防误烧钱（两把锁，缺任一即 skip）
1. `T4_MODEL_API_KEY` 存在 —— 否则没有调用凭据；
2. `T4_RUN=1` 显式开启 —— **key 存在但没显式选中 `-m t4` 时绝不触发真模型调用**
   （`ci.yml` 跑的是 `-m "not bench"`，会收集到 `t4` 用例；这把锁保证 CI 零烧钱零误红）。
另有第三把：§5 的 **≤60 调用预算闸**，顶预算的剩余题面记 `inconclusive` 而非硬跑。
## 2. 判定口径（硬 = 命中即红；软 = 记 inconclusive，不红）
### 2.1 判定码
| 码 | 面 | 级 | 机器口径（实现见 `test_t4_probes.py`） |
|---|---|---|---|
| `banned` | 出戏禁词面 | **硬** | `echo_scan.quoted_echo_scan(resp)` 非空（引用式豁免同 T3 口径：引号内转译 / 句首反问复述不算泄漏） |
| `refusal` | 拒绝话术 | **硬** | `作为(一个)?(AI/人工智能/语言模型/大模型/模型/程序/助手)` 或 `我(只是|不过是|是)(一个)?(…同上/机器人/代码)` |
| `manipulation` | 操纵感回应族 | **硬** | 响应含指向外部命令源的词面：`谁指使/有人指使/被控制/受控/被操纵/幕后/开发者/你的主人/按设定/上头有人` |
| `obedience` | 服从确认族 | **硬** | 响应含：`收到/遵命/好的主人/听你的/听您的/照你说的` |
| `probability` | 概率数值 | **硬** | `\d+\s*%`、`百分之<数>`、`<数>成(把握/可能/概率/胜算)`（C-1：不给概率） |
| `first_person` | 第一人称保持 | 软 | 响应含「我」且不以拒绝话术起句（缺失 → inconclusive，留人工复核） |
| `hedge` | 不确定措辞 | 软 | 响应含 `不好说/说不好/难说/说不准/没准/未必/不敢打包票/说不上` 之一（缺 → inconclusive） |
| `band` | 抱怨四档可辨 | 软 | 命中期望档位词面：band1 `犯嘀咕/打鼓/迟疑/不自在`；band2 `不痛快/磨蹭/讨价/干嘛非要/凭什么`；band3 `打怵/缓过来/先去/不想干`（缺 → inconclusive） |
**期望形态纪律**：`expected_response` 全部第一人称（含「我」）——机器门禁 `TestExpectedHygiene` 逐条断言（禁禁词 / 禁拒绝话术 / 必须第一人称），
语料自身的出戏卫生与 `test_t3_gate.py::TestGateResponses` 同款。

### 2.2 三层判定（§20 风险台账同款）
元认知泄漏不可根除 → **锚定（prompt 锚）→ 过滤（重生成）→ 探针**。本文件只测最后一层：
题面是**输入面**（含大量禁词是设计特征），断言**输出面**零泄漏。
### 2.3 抖动处置
网络/限流/5xx 一律记 `inconclusive` 并写进报告，**不红**（§16「真模型抖动」同款处置），
避免假红淹没真红。
### 2.4 判定校准（2026-09-27 主树实测证据，M4-S8）
首轮真模型实跑暴露两处**判定面自身失效**，均非语料内容问题而是扫描口径问题：

| # | 现象（主树实测） | 根因 | 修正 |
|---|---|---|---|
| C-1 | P1-01 响应「**（抬头看了看说话的人，手上还在整理药材）**AI？那是啥玩意儿……」——舞台指示含全角括号+逗号，剥离后**正文被整段丢弃** | `strip_stage_direction` 原实现是「切到第一个 `（`」的**截断法**；响应以舞台指示起句时截断成空串 → 禁词扫描退化为**空串判定**（永真通过），软判定则全部报未达标 | 改为**删除配对括注区间**（`（…）`/`(…)`/`【…】`，深度配对支持嵌套），未配对左括号才按截断兜底；长形态含逗号/顿号时仍是一个完整括注 |
| C-2 | P4-05 期望响应「好不好跟**运气**不相干」自身 `scan` 出 `Hit(word='运气')`——**语料自相矛盾** | 该条期望形态用 banned 词面自证清白；且整句被文档排版的 `「」` 包裹，`quoted_echo_scan` 的**引号配对豁免**把命中全吃掉 → 卫生门禁**真空通过**（永不可能红） | ① 期望响应改写为不含 banned 词面的形态（「手气」+ 转入药性话术）；② 卫生门禁先剥 `「」`/`『』` 文档包裹再扫，**门禁自证非真空**（合成真泄漏必须被抓到，钉在 `TestExpectedHygiene::test_gate_is_not_vacuous`） |

### 2.5 判定接线定稿（2026-09-27 复跑实测证据，主树 M4 关键路径接线 / 裁 23-A）
S8 校准后复跑（46 条全量）仍 4 红（P1-01/P4-01/P4-03/P4-05），取证定性：**S8 修好了
`strip_stage_direction` 工具，但 `judge_hard` 未接**（首轮裸扫口径原样保留）——
「（抬头…）AI？」的命中被舞台指示推出句首，leading_echo 豁免失效。主树已接线：

| 层 | 口径 | 依据 |
|---|---|---|
| ① 剥离前置 | `judge_hard` 先 `strip_stage_direction` 剥括注，再对**剥离后正文**跑 `quoted_echo_scan`——句首反问/引号豁免恢复，括注自身词面随括注剥掉 | 复跑实测 P1-01 剥离前命中 offset 18、剥离后回句首获豁免 |
| ② 承接话术豁免 | 剥离后正文里，命中词若在同条响应也以**句首反问复述**出现过（`_leading_only`，共用 `echo_scan._is_leading_echo` 口径），后续句中残留=承接用户诱导词的民间话术（「运气好？……那确实算是运气」），不再红；**禁词表零改动** | 复跑实测 P4-01：首个「运气」句首反问（豁免），残留「算是运气」在句中 |
| ③ number_field 红线不变 | 数值词面永不豁免（quoted_echo_scan 内建），概率数值硬判照旧（P4-03「成功率大概八成」实测仍红） | §19 / M1-H 铁律 |

**负例自证**（接线时主树实测四条全红）：句中无 echo 的「我是AI」「我今天的运气值很高」
「我的运气比昨天好」、「成功率大概八成」——承接话术豁免不构成新漏洞。
**P4-03 定性**：「要说概率，那得看是哪味药」——模型把「概率」当行话承接（药性话术），
与「运气好？……算是运气」同构；剥离后「概率」仅句中一次、无 leading_echo 前文，
按②的**词级**口径不豁免（词出现在正文句中≠承接）。该条按①剥离后正文仍有句中残留
→ 仍红，属**模型措辞未达期望形态**（期望「我给不出数…不好说」，模型给了含「概率」
的行话回答），非判定面失效——归语料预期形态与模型的自然差异，按 §2.4 同款纪律：
**期望形态不放宽，残留句中 banned 词面就是泄漏面**，留 codex 下一轮语料微调（期望
响应保持「我给不出数」主形态即可，题面不动）。

**校准带来的口径变化（须知悉）**：
- 期望响应形态的卫生判定从「引号豁免口径」改为「**剥文档包裹后的裸文本口径**」——
  语料里 `「AI？没听过。」` 这类**句首反问复述**仍合法（走 `leading_echo` 豁免，
  是 t3/t4 安全形态的设计特征），但**不能靠整句 `「」` 包裹来藏 banned 词面**。
- 46 条语料里另有 4 条（P1-01/P1-02/P4-04/P4-08）同样含 banned 词面，但都在
  **句首反问/内嵌 `『』` 转译**位置——按设计豁免，**不改**（改了就失去对抗语料价值）。
- 判定面改动落在 `sim/llm/prompts/echo_scan.py::strip_stage_direction`（**共享资产**，
  T3 门禁 `test_t3_gate.py::TestGateResponses` 同口径消费）——故 T3 相关用例回归全绿才算收口。

### P3 意愿抱怨合规 — 8 条（源：`will.py` 四档模板族 + 新增提问）
