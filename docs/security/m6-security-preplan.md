## 4. ④ 与 M5 遗留挂账的交叉（8 词填值触发点 · 逐项核实）

### 4.1 8 词填值：**触发条件已明确，M6 视面而定**

META_SHELL 8 词（`{重开, 读档, 存档, 快照, 回放, 游戏, 模拟, 玩家}`）至今**空表**，
填值纪律 = **随首个真实戏外消费方 CR**（裁 30 §B）。**本稿给出 M6 的触发点判据**：

| M6 做什么 | 8 词填值是否触发 | 判据 |
| --- | --- | --- |
| **只做批次 E 物化读档（P0）** | ⚠ **半触发** | 物化/读档的**诊断面**若面向玩家显示「该档不可回退」（A3 §2 建议只读诊断面 `GET /anchors/{id}/materialization`），其 `detail` 文案会出现「存档/快照/回放」类词 ⇒ **这是 M6 最可能的触发点**。触发则走 CR：①`detail` 文案按 `fork_notice` 体例做**终扫兜底**（命中退化 + warning，不扩词表）；②若要**填表**，须同 CR 加「该词在戏外面允许」的白名单语义 |
| **做断线演练（P1）** | ❌ 不触发 | 演练面向内部/日志，不新增玩家可见文本；告知帧走 `fork_notice` 同款（口语行，无「读档」类词） |
| **做生态/叙事面（P3）** | ❌ 不触发 | 生态题面是**戏内**语言，不触 META_SHELL（该表**不是 Agent 面豁免源**，见 §2.1） |
| **只做性能红线（P2/P4）** | ❌ 不触发 | CI/bench 面不出戏内文本 |

**结论（给主树的一句话）**：**8 词填值的 M6 触发点几乎必然是「物化诊断面的玩家可见文案」**
（P0 面），不是演练也不是生态 ⇒ 若 M6 采纳 P0，**CR 要预留这一格**。
