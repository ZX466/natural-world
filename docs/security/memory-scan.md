## 0. 为什么必须在记忆写入点扫描

污染循环推演（本项目最高优先级技术安全风险）：

```
LLM 输出 reason（不可信输入）
   → ①闸门禁词扫描拦下大部分
   → 漏网词面进入记忆写入（MemoryEntry.content，append-only）
   → 记忆检索进 prompt（§8 [记忆] 段）
   → 模型读到自己的「出戏残留」并强化 → 下次 reason 更容易出现同类词面
   → 写入更多记忆 → 自我强化循环
```

不可修复性来自三件事叠加：记忆是身份基石（铁律 4）、事件/记忆 append-only（§12/§19）、检索权重会让高 salience 的污染条目反复入选。**写入点（①之后、落库之前）是最后一个低成本拦截点**——之后只有「标记无效」这种带痕补救。

## 1. 扫描位置：唯一写入入口

M1 落地要求：**所有记忆写入收敛到一个入口函数**（示例签名，实现可调整）：

```python
class MemoryWritePipeline:
    def write(
        self,
        npc_id: str,
        content: str,            # 候选记忆文本（已是叙事化第一人称）
        *,
        source: Literal["reason", "dialogue", "event", "interoception"],
        event_seq: int | None,
        importance: float,
        emotion_tag: str | None,
    ) -> WriteResult: ...
```

上游只允许三个来源，且**全部先经各自的叙事化产物**（不得传 LLM 原始输出）：
1. `reason`：Intent.reason（闸门已扫一遍，这里是第二道）；
2. `dialogue`/`event`：见证事件叙事化摘要（ PerceptionFrame.content 派生）；
3. `interoception`：内感受叙事化文本（M1-H 已保证无数值词面）。

CR 检查点：grep 全仓对 MemoryEntry 的构造/INSERT，必须全部经 `MemoryWritePipeline.write()`；绕过即 CI 红（与 G2「闸门唯一通道」同款守卫思路）。

## 2. 扫什么：单一禁词表来源

- 复用 prompt 装配出口的同一张禁词表（**同一模块、同一份常量**，禁止两处各维护一份导致漂移）：硬词 = m1-checklist M1-A 全集（`AI`/`模型`/`模拟`/`游戏`/`角色扮演`/`tick`/`entity_id`/`玩家`/`运气`/`luck`/`seed`/`随机数`/`重开`/`重来一次`/`存档`/`读档`/`profile`/`prompt`/`token`）+ 持久化词汇（`分支`/`branch`/`abandoned`/`重放`/`快照`/`回放`/`snapshot`，对应 M1-G）。
- 匹配规则：中英文大小写不敏感、**子词边界**（避免误伤「模特儿」「棋子运」这类正常戏内词——维护一个白名单例外表，例外表变更走 CR）；数值+字段名模式（`hunger:72` 类）同 M1-H 一并拦截。
- 表的运行形态：编译成正则集 + 词面集，模块级加载一次；`scan(text) -> ScanResult(hits: list[Hit], cleaned: str)` 纯函数，无 I/O，方便单测。

## 3. 命中处置：改写优先、拒写次之、全量记录

| 处置 | 条件 | 动作 |
|---|---|---|
| **改写**（首选） | 命中 ≤2 处且命中词可机械替换为世界内等价物 | 走「安全改写映射表」：`游戏→日子/买卖`、`重开→从头再来（戏内语义）→直接拒写`、`tick→时辰`、`存档→账册`…映射表与禁词表同模块维护。改写后**再扫一遍**，通过才写。改写记录进 WriteResult 供观测 |
| **拒写**（次选） | 命中 >2 处 / 映射表无对应词 / 源文本结构性可疑（如整段是元信息讨论） | 不落库；返回结构化拒绝原因；**记忆缺失比记忆污染安全**——这是本设计的底线判断 |
| **记录**（必做） | 任何命中 | 命中事件写 dev 日志（structlog dev channel，含 npc_id/source/命中词/处置），进安全周观测指标；同一来源连续命中 → 提升该来源的 T4 探针权重 |

关键区分：改写只做**词面级**机械替换，不做语义重写（语义重写 = 另一次 LLM 调用 = 又一个污染面与成本面，M1 不做）。

## 4. append-only 下的补救：标记无效 + 重写

适用范围：本设计上线**前**已落库的历史污染条目，以及上线后发现的漏网条目。原则：**永不 UPDATE/DELETE 内容字段**（事件溯源纪律同等适用于记忆）。

```python
# 记忆表增加两列（迁移经 alembic，属 opencode 域协同项）
superseded_by: str | None   # 指向替代条目 id；NULL=有效
invalid_reason: str | None  # 'banned_word' / 'manual_review'
```

补救流程：
1. 审查（人工或 T4 探针）确认某条记忆含出戏词面 → 生成**替代条目**（改写后文本或显式世界内摘要），正常走写入管线；
2. 旧条目置 `superseded_by = 新条目id`（一次 UPDATE 两列，仅限这两个治理列，不属于内容篡改）；
3. 检索层一律过滤 `superseded_by IS NOT NULL` 的条目——旧条目留在库中供审计，不进 prompt；
4. 快照序列化同样排除被取代条目（快照体积顺手受益）。

T2 回放注意：记忆治理列变更**不进世界事件流**（它不是世界状态变化，是存储层卫生），需在回放测试中明确该约定，避免回放断言误伤。
