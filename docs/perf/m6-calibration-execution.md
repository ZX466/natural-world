## 2. POWER_MAX_BIAS 裁值（✅ 已给，确定性、不依赖跑分）
### 2.1 判据链（既有依据）
- 机制：`sim/npc/utility.py:53` `POWER_MAX_BIAS=0.2`（裁 34-2 采 P10 提案）；偏置 = `power × POWER_MAX_BIAS`，**只作用于社交/活动两列**（`_POWER_SOCIAL_ACTIONS` = `request_chat`/`wander`），**生存列零触碰**。
- 派生判据（P10 §3）：`flip_rate ≤ 0.25`（= 动作分布「被操纵感」守卫，与 codex 红线 C 一箭双雕）+ 熵不坍缩。
- **实测越界**：`sim/tests/test_m6_power_utility.py:85` 钉（seed=42 口径）**flip=0.26 > 0.25**（卡亦引用）。

### 2.2 本单实测（**同钉同 seed=42 同夹具**，用等价缩放 power 实现，**不改常数**）
> 原理：偏置项 = `power × POWER_MAX_BIAS`；`power=[s]*50` 与常数 `0.2×s` **逐位等价**（`utility_scores_matrix` 中无其他对 `POWER_MAX_BIAS` 的依赖）⇒ 可用 `s` 扫出「换常数」的效果。
| 等效 bias | flip_rate | 熵† | top 动作 |
|---|---|---|---|
| **0.20（现值）** | **0.260** ✗ 超 0.25 | 0.881 | eat:35 |
| **0.18（裁值）** | **0.240** ✓ | 0.855 | eat:36 |
| 0.15（备选） | 0.200 ✓ | 0.795 | eat:38 |
| 0.25 | 0.260 | 0.881 | eat:35（**在该夹具饱和**：0.20→0.25 不改判） |
| 0.10 | 0.140 | 0.680 | eat:41 |
† **口径警告**：此熵为本夹具**真实动作分布**的熵（eat 主导 ⇒ 0.6–0.9 量级），**与 P10 §2.1 的 2.52/2.41 是不同口径**（那里是合成 score 面）⇒ **本裁值只依据 flip（同钉同 seed 同口径），熵不得跨口径引用**；熵守卫（红线 C）必须在 P10 同口径下另测（见 §5 委托）。

### 2.3 **裁值：`POWER_MAX_BIAS = 0.18`**
| 理由 | 依据 |
|---|---|
| ① 守卫合规且余量来自实测（非插值） | flip **0.240** ≤ 0.25（余量 4%），**确定性测试（seed=42）不随机器漂移** ⇒ 可作硬断言 |
| ② 取「满足守卫的最松值」而非最小化 | 权力面的存在意义是**让权力被感知**（D-10/§17 设计意图）；过度收紧=让机制「无感」=功能空转。0.18 相对 0.20 仅降 10% 偏置，**叙事效果基本保留** |
| ③ 熵守卫未被削弱（P10 口径） | P10 曲线 0.1→熵 2.48、0.2→熵 2.41；0.18 约 2.43 ⇒ 仍高于 2.4 一线 |
| ④ 备选 0.15 的理由不成立 | 0.15 ⇒ flip 0.200（余量 20%），但**没有任何数据支持「margin 越大越好」**；守卫是**上限**不是优化目标。若 Claude 更看重安全余量，0.15 是已备好的下档（**给出数即可同 CR 改**） |

## 4. 复跑判据与「跑前+跑后双探针」（**新增操作纪律**）
**重派条件（可检查，不猜）**：
```bash
# 连续 3 次全部 <=1.8（相对 2.0 阈值留 10% 余量）才重派定标轮
uv run python -m sim.tests.bench.throttle_probe   # 读 throttle_ratio

uv run python -m sim.tests.bench.throttle_probe
```
**跑前+跑后双探针（防「跑中降频」污染基线）**：
- 旧纪律只查**跑前**；但 bench 是分钟级负载，**跑中**一样可能掉进临界带 ⇒ 单次跑前读数不足以证明过程健康。
- 新纪律：**跑后立刻再探一次**。若跑后 >2.0 ⇒ 该轮中位值**作废重取**（不是放宽阈值）。
- 成本：+25s/轮（可接受，相对分钟级 bench）。
