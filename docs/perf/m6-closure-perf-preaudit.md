## 2. ② 机器门现状终判 + **M6 版性能门口径裁定建议**

### 2.1 三源互证：机器处于「周期性回降的非稳定态」
| 源 | 数据 | 含义 |
|---|---|---|
| **P6 六笔序列**（本域，`m5-closure-perf-ledger.md` §8） | `1.599 → 2.278 → 2.337 → 3.287 → (冷却) 1.615 → 1.997` | **同一台机、数分钟内**给 **3.287 与 1.615** 两个相反判定 ⇒ **单次读数不可信** |
| **cline C6 收官台账**（`docs/config/m6-c6-closure-final.md`） | 同轮 **2.463**；bench 期间自旋 **3.059 / 2.828**；结论原文「**回落不是稳定态，机器仍会周期性回降**」 | 与 P6 互证；**C4「连续 5 笔健康」的回落结论被推翻** |
| **本单实测**（M6-P7） | 跑前 **1.835** → 跑中**降频**（4 笔 soak 门自检 skip）→ 跑后 **1.875** | 三次读数全部**贴门**（1.8–2.0），且**跑中确实越门** ⇒ 即使「单次 ≤2.0」也不保证整段健康 |
> ⇒ **终判**：门 2 判据**不能用单次读数**；须**连续段**（P5 已定：**连续 3 次 ≤1.8**）+ **跑前+跑后双探针**（P5/P6 纪律）。

### 2.2 **裁定建议：三案 advisory 状态收官 = 可接受**（对照 M5 先例）
**先厘清「三案」在 M6 的真实状态**（比卡的前提更精确——不笼统称「三案未翻」）：
| 案 | M6 真实状态 | 与 M5 的差别 |
|---|---|---|
| **POWER** | ✅ **已翻硬**（`POWER_MAX_BIAS=0.18`，flip 0.240≤0.25，确定性钉） | M5 是 advisory 未翻 ⇒ **M6 已超前** |
| **FIRE** | ✅ **语义已由机器无关机制钉覆盖**：`test_m6_fire_mechanics.py:32`（格数 ×10 ⇒ 耗时 ≤15x = O(G) 红线，**中位+多轮抗抖**）、`:55`（聚合 ≤1 条/tick = W-D3）、`:73`（F≤50 防御） | M5 时机制面未落、钉 skip；**M6 已落且钉在跑** |

**可接受的 4 条依据**：
1. **M5 先例成立**：M5 收官时三案**全 advisory**，台账 §1.2 自陈「**三案红线不是没做完，是排在接线后面**」⇒ advisory 收官**有先例且被采认**。
2. **M6 严格强于 M5**：M5 缺的是**接线（前置）**；M6 的接线已落（inject ✅/fire*.py ✅/power 消费 ✅），缺的是**机器窗**与**CHAOS 消费点**（后者是功能缺口，见条件 2）。
3. **机器不稳**≠**代码/设计风险**：soak 门**按设计 skip**（P6 仲裁结案：「不是代码回归」）；且**漂移比判据不受降频影响**（只有绝对阈值受影响）⇒ **无假绿风险**，只是**无法收口绝对阈值**。
4. **P4 红线已守**：`thresholds.py` 三案**零命中**（实测）⇒ 「零新行」未被违反；advisory 收官**不产生违规**。

**附 4 条条件（不满足则本建议降级为「待条件」）**：
1. **FIRE 的等效性须在收官记录中明示**：其红线已由**机制钉**（非 thresholds 行）覆盖 ⇒ 收官门须写「**FIRE 红线已守（机制钉口径）**」，避免被读成「FIRE 未做」。
2. **CHAOS 的缺失须写成「设计前置未落」而非「性能未定」**：`chaotic()` 消费点属**功能缺口**（归 Claude 域），**不应阻塞性能门**；否则会把功能缺口误记为性能缺口（P11 教训同型：**别把口径问题记成预算问题**）。
3. **重派判据与双探针纪律须随收官记录**：**连续 3 次 ≤1.8** + **跑前+跑后双探针**（跑后 >2.0 ⇒ 中位作废重取）。
4. **skip 分型口径须进收官门读数**：**4 笔降频 skip ≠ 回归**（§4），收官门报数须附 `-rs` 分型。

> **若采「不可接受」**，则等价于要求：**先落 CHAOS 消费点 + 等机器窗**才能收官。但前者是**功能**（不属性能门），后者**不由本域控制**（环境）⇒ 「不可接受」会把性能门绑在非性能事项上。**故建议采「可接受」**。

## 5. ⑤ M6 性能面收官结论（三态）
> **【可收官带限制】**
> **一句话**：M6 性能面**可收官**——全程**零新增阈值行**（P4 红线守住）、**POWER 已翻硬**（flip 0.240≤0.25）、**FIRE 红线已由机器无关机制钉覆盖**；**唯一未翻的 CHAOS 是「消费点未落」的功能前置 + 机器窗不稳**（两者均不属性能门可控范围），故以 **advisory 状态收官**，**与 M5 先例同型且更强**。
> **限制清单（4 条，须随收官记录）**：
> 1. `CHAOS_TICK_LIMIT_MS` 维持 advisory（前置：消费点落地 + 定标机实测）；**重派判据 = 连续 3 次探针 ≤1.8 + 跑前/跑后双探针**。
> 2. `FIRE_REPATH_BUDGET_PER_FRAME` / `FIRE_SPREAD_INTERVAL_TICKS` 维持 advisory（机制钉已守 O(G)/聚合，数值待定标机）。
> 3. `MATERIALIZE_LIMIT_MS` 维持 advisory（**W 归架构域，未定 ⇒ 不可先写死**）。
> 4. **7 日完整 soak 未跑**（`PI_M2_FULL_SOAK` 默认关）⇒ 收官门须登记「未跑」，非「已通过」。
> **不选另两态的理由**：**「待条件」**会暗示存在**本域可控但未做**的动作（实际只剩环境窗 + 他域功能）；**「不可收官」**会把性能门绑在**功能缺口（CHAOS 消费点）**上——违反 P11 教训（别把口径/功能问题记成性能问题）。
