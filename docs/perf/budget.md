# 性能预算（docs/perf/budget.md）

> 依据：`DESIGN.md` §9/§10/§12/§13/§16（v2.1）。基线冻结，本文只给预算与采集点，不做实现。
> 目的：在确定性 tick 内核成型前锁定每 tick 成本上限，避免 M0/M1 返工。
> 校验约定：**运行时刻名义均耗 + 上限两列均须有效**，且「上限合计 ≤ 每 tick 硬上限」。

## 0. 每 tick 硬上限

- **时间锁定**：1 tick = 1 游戏秒；基准速度 **1x = 60 tick/s → 每 tick 预算 16.6ms**（§10）。
- 例外倍率：4x → 240 tick/s → **4.16ms/tick**；16x → 960 tick/s → **1.04ms/tick**（见 §4 超速对策，不适用本表假名）。
- 战斗时间尺（v2.1，§9）：战斗局部切 1 tick = 1 真实秒 → 该区间每 tick 预算 **1000ms**，战斗结算（交换单元 resolve）全局域吸收，不进 16.6ms 表。
- 判定：`tick p99 < 预算 50%（8.3ms at 1x）` 为 M0 起强制回归线（§bench-plan），预算表以 p99 口径给名义均耗。

## 1. 预算表（1x = 16.6ms/tick，确定性内核在异步事件循环，WS 网络不进 tick 临界区）

| 子系统 | 名义均耗 (ms) | 上限 (ms) | 说明 |
|---|---|---|---|
| 时钟 / 日历 | 0.02 | 0.05 | tick 递增、昼夜/集市/节气检查，O(1) |
| RNG / 熵（C5 确定性流） | 0.03 | 0.10 | 多流确定性 RNG + inject 真随机重播种日志 |
| 事件 apply（C4 事件溯源） | 1.00 | 2.00 | 稳态 ~20 事件/tick（50 NPC 决策产出），p99 50 事件 |
| L1 效用推进（50 NPC） | 4.00 | 6.00 | needs/schedule/utility/memory 衰减；同构数据向量化 |
| 感知传播（视/听/触） | 1.50 | 3.00 | 空间分区后可见对子射线 + 1/r 衰减；嗅觉 M2 另计 |
| 快照摊销（每 1000 tick） | 0.20 | 0.50 | ≤5MB gzip 异步卸载，非阻塞 tick |
| WS 编码（增量 patch） | 0.20 | 0.50 | 每 client 增量 diff，不打全量；0.20 为保守上限，按 5–10Hz 合批（H-4）摊销 ~0.04ms/tick |
| **合计** | **6.95** | **12.15** | ≤ 16.6 ✓，名义合计留 58% 余量给 4x 档 |

**L0（§13，地图外千人级统计模拟）**：每分钟推进一次，独立预算 ≤500ms/游戏分钟，运行在独立 worker（asyncio.to_thread 或进程池），**不占用 tick 临界区**；其与 tick 的交互仅 1 次/游戏分钟快照切片，摊销 ~0.1ms/tick，已计入快照摊销量。

## 2. 子系统预算细项

### 2.1 时钟/日历
- tick 自增、mod 检查（昼夜节律、集市日）。
- 禁止 `datetime.now()`（C5）：一切经 clock 流。
- 上限 0.05ms = O(1) 常数，无优化空间，基准即门槛。

### 2.2 RNG/熵

- 预算语义：每 tick RNG 成本按「draw 数 × 单 draw 耗时」计。L1 规模 50 NPC × ~4 draws/tick = 200 draws，实测 ≤0.10ms（表内 0.03/0.10 即此口径）。
- 聚合 1M draws 只是警戒线（**实测 219ms**，2026-09-19 TASK-002 先行实测，逐调用 numpy 路径），不作为每 tick 硬预算；阈值 300ms 见 bench-plan。
- 若 L1 每 tick draw 数暴涨（如 >1000），逐调用路径会逼近 0.10ms 上限 → 回退向量化批量抽取（`gen.random(size=N)`，实测 2.4ms/1M）。
- `inject()` 每次 OS 熵 + 日志写，发生频率低（NPC 重大决策/致命一击/季节/偶遇/意外，§11）。

### 2.3 事件 apply（最大颗粒度风险点）
- 全部写路径 = `apply(event)`（C4），实体 frozen。
- 每 tick 事件数：L1 50 NPC 各产 0–2 决策事件 + 感知/经济/建造事件 → 稳态 ~20/tick，p99 50。
- 单事件 apply 预算 0.02ms × 50 = 1.00ms 名义；p99 突发 50 事件 = 2.00ms 上限。
- 保证：按 seq 顺序批处理，禁止单事件同步 I/O；事件先入内存队列，SQLite 落盘批量（§hotspots-3）。

### 2.4 L1 效用推进（50 NPC）
- 每人每 tick：needs 衰减 + schedule 定位 + utility 打分 + memory 衰减/新条目写入（仅见证者）。
- 同构主循环走 numpy/数组批量（与 L0 共用批内核），避免逐对象 Python dict 热循环。
- 名义 4.00ms（50 × 0.08ms），上限 6.00ms；M2 起 NPC 满属性（OCEAN/PAD/关系/记忆）后复测，若破预算先砍 memory 衰减节拍（事件驱动而非每 tick）。

### 2.5 感知传播（视/听/触）
- 视觉：射线遮挡、完全阻断（§7）——只对「空间分区内候选对子」做射线；光照/雾修正为低频 pass（每 N tick 或触发式）。
- 听觉：∝1/r、穿墙衰减不阻断——距离预过滤 + 每接收者 top-k，无射线。
- 触觉/内感受：接触生效 + 需求叙事化，事件驱动、近零成本。
- 嗅觉（M2）∝1/r² 风向主导：引入持续源 + 风场，预计算梯度，每 tick 增量扩散，不逐对计算。
- 名义 1.50ms，上限 3.00ms；超过即启用空间分区/增量可见集（§hotspots-1）。

### 2.6 快照摊销（§12 v2.1）
- 每 1000 tick 全量快照 ≤5MB（gzip），同分支保留最近 8 份 + 每日首份。
- 快照序列化/压缩放 worker 异步；tick 内仅提交指针与 dirty 标记，摊销 0.20ms。
- 快照 tick 本身允许暂挂于 p99 阈值之外（单次 ≤500ms，后台完成），但不得阻塞 tick 循环主线程。
- 主库稳态 <2GB（冷归档阈值策略见 §hotspots-3）。

### 2.7 WS 编码（表现层，越 sim 边界）
- Phaser 只画 canvas，React 只画 canvas 外 UI（§4 硬约束）。
- 每 tick 增量 patch 编码 ~0.20ms；候选（每 1/15s 的 5–10Hz）合并 batch，不全量、不逐 tick 逐事务。
- 网络 I/O 在 uvicorn 边界，不占 tick 临界区；此列是「编码」而不是「发送」。

## 3. 自洽性检查

- 合计名义 6.95ms ≤ 16.6ms ✓；合计上限 12.15ms ≤ 16.6ms ✓。
- L1 + 感知 = 5.50ms 名义，占 60% 预算——M0–M1 优化主战场。
- 4x 档 4.16ms 已低于名义合计 6.95ms ⇒ **4x/16x 不能靠「更快的 tick」实现**，必须走 §4 超速对策（降采样/合并 tick），避免用 100% CPU 追倍率。
- 战斗时间尺 1000ms/tick 与正常档完全解耦，预算互不竞争。

## 4. 超速对策（4x / 16x）

| 倍率 | 每 tick 预算 | 方案 |
|---|---|---|
| 1x | 16.6ms | 本表 |
| 4x | 4.16ms | 降采样：L1 每 4 tick 推进一次、感知每 2 tick；时钟/RNG/apply 全速 |
| 16x | 1.04ms | 合并 tick：内核按 60 tick 语义批处理，UI 按 960 tick/s 出帧；或接受「快进 = 低保真节拍」（文档宣告，不悄悄降质） |

快进期间确定性不变（seed 相同 → 结果一致），只是节拍粒度变粗；回归线单列 4x/16x 阈值（见 bench-plan）。

## 5. 采集与告警（量入为出，防回归）

- 每 tick 在 `structlog` 记：`perf.tick_ms`、各子系统分段计时（clock/rng/apply/utility/perception/snapshot/ws_encode）。
- 每次 LLM 调用记：`tokens`、`latency_ms`（对齐 §15 成本治理：单决策 <2k tok、决策延迟 P95<8s——注意那是 LLM 异步延迟，与本表 tick 预算正交）。
- nightly 汇总：tick p99、p999、超预算秒数、各子系统占比；超阈值告警进 CI 红灯（§bench-plan 阈值）。
