# 性能预算（docs/perf/budget.md）

> 依据：`DESIGN.md` §9/§10/§12/§13/§16（v2.1）。基线冻结，本文只给预算与采集点，不做实现。
> 目的：在确定性 tick 内核成型前锁定每 tick 成本上限，避免 M0/M1 返工。
> 校验约定：**运行时刻名义均耗 + 上限两列均须有效**，且「上限合计 ≤ 每 tick 硬上限」。

## 0. 每 tick 硬上限

- **时间锁定**：1 tick = 1 游戏秒；基准速度 **1x = 60 tick/s → 每 tick 预算 16.6ms**（§10）。
- 例外倍率：4x → 240 tick/s → **4.16ms/tick**；16x → 960 tick/s → **1.04ms/tick**（见 §4 超速对策，不适用本表假名）。
- 战斗时间尺（v2.1，§9）：战斗局部切 1 tick = 1 真实秒 → 该区间每 tick 预算 **1000ms**，战斗结算（交换单元 resolve）全局域吸收，不进 16.6ms 表。
- 判定：`tick p99 < 预算 50%（8.3ms at 1x）` 为 M0 起强制回归线（§bench-plan），预算表以 p99 口径给名义均耗。

## 2. 子系统预算细项

### 2.1 时钟/日历
- tick 自增、mod 检查（昼夜节律、集市日）。
- 禁止 `datetime.now()`（C5）：一切经 clock 流。
- 上限 0.05ms = O(1) 常数，无优化空间，基准即门槛。

### 2.2 RNG/熵

- 预算语义：每 tick RNG 成本按「draw 数 × 单 draw 耗时」计。L1 规模 50 NPC × ~4 draws/tick = 200 draws，实测 ≤0.10ms（表内 0.03/0.10 即此口径）。
- 聚合 1M draws 只是警戒线（**实测 219ms**，2026-09-19 TASK-002 先行实测，逐调用 numpy 路径），不作为每 tick 硬预算；阈值 300ms 见 bench-plan。
- 若 L1 每 tick draw 数暴涨（如 >1000），逐调用路径会逼近 0.10ms 上限 → 回退向量化批量抽取（`gen.random(size=N)`，实测 2.4ms/1M）。
- `inject()` 每次 OS 熵 + 日志写，发生频率低（NPC 重大决策/致命一击/季节/偶遇/意外，§11）。

### 2.3 事件 apply（最大颗粒度风险点）
- 全部写路径 = `apply(event)`（C4），实体 frozen。
- 每 tick 事件数：L1 50 NPC 各产 0–2 决策事件 + 感知/经济/建造事件 → 稳态 ~20/tick，p99 50。
- 单事件 apply 预算 0.02ms × 50 = 1.00ms 名义；p99 突发 50 事件 = 2.00ms 上限。
- 保证：按 seq 顺序批处理，禁止单事件同步 I/O；事件先入内存队列，SQLite 落盘批量（§hotspots-3）。

### 2.4 L1 效用推进（50 NPC）
- 每人每 tick：needs 衰减 + schedule 定位 + utility 打分 + memory 衰减/新条目写入（仅见证者）。
- 同构主循环走 numpy/数组批量（与 L0 共用批内核），避免逐对象 Python dict 热循环。
- 名义 4.00ms（50 × 0.08ms），上限 6.00ms；M2 起 NPC 满属性（OCEAN/PAD/关系/记忆）后复测，若破预算先砍 memory 衰减节拍（事件驱动而非每 tick）。
- **M2-P1 实测（2026-09-20，满属性代表载荷 50 NPC）**：向量化暖态中位 **~0.02ms/tick**（单 NPC ~0.0004ms，≪ 逐人预算 0.12ms）；逐对象热循环对照 **~4.4ms**（≈ 名义 4.00ms，即名义值实际描述的是「未向量化写法」的量级）。
- **红线**：全量 `L1_UTILITY_TICK_LIMIT_MS=6.0`（= 上限表）、逐人 `L1_UTILITY_PER_NPC_LIMIT_MS=0.12`、断线兜底 `L1_OFFLINE_FALLBACK_LIMIT_MS=0.20`。
- **LLM 断线降级路径开销**（DESIGN §3）：L1 兜底执行计划队列（每股 pop 一步 + 常数校验）实测 ~0.001ms/tick，见 bench `test_l1_offline_fallback_plan_queue`。

### 2.5 感知传播（视/听/触）
- 视觉：射线遮挡、完全阻断（§7）——只对「空间分区内候选对子」做射线；光照/雾修正为低频 pass（每 N tick 或触发式）。
- 听觉：∝1/r、穿墙衰减不阻断——距离预过滤 + 每接收者 top-k，无射线。
- 触觉/内感受：接触生效 + 需求叙事化，事件驱动、近零成本。
- 嗅觉（M2）∝1/r² 风向主导：引入持续源 + 风场，预计算梯度，每 tick 增量扩散，不逐对计算。
- 名义 1.50ms，上限 3.00ms；超过即启用空间分区/增量可见集（§hotspots-1）。
- **真实引擎实测（2026-09-20 F06，50 NPC/64×64，C06-③ 合入）**：视觉暖态 mean 3.0–3.3ms（median ~1.7ms）/ 听觉暖态 mean 3.0–3.3ms；首轮 LOS 对称缓存冷启动 7.6–8.2ms（一次性，bench 已 `warmup_rounds=1` 剔除）。3.00ms 为预算目标值（暖态贴线），红线 3.6（+20% 慢机余量）；cProfile 无意外热点（assemble 36% + salience 29% + LOS 命中缓存 10%）。

### 2.6 快照摊销（§12 v2.1）
- 每 1000 tick 全量快照 ≤5MB（gzip），同分支保留最近 8 份 + 每日首份。
- 快照序列化/压缩放 worker 异步；tick 内仅提交指针与 dirty 标记，摊销 0.20ms。
- 快照 tick 本身允许暂挂于 p99 阈值之外（单次 ≤500ms，后台完成），但不得阻塞 tick 循环主线程。
- 主库稳态 <2GB（冷归档阈值策略见 §hotspots-3）。

### 2.7 WS 编码（表现层，越 sim 边界）
- Phaser 只画 canvas，React 只画 canvas 外 UI（§4 硬约束）。
- 每 tick 增量 patch 编码 ~0.20ms；候选（每 1/15s 的 5–10Hz）合并 batch，不全量、不逐 tick 逐事务。
- 网络 I/O 在 uvicorn 边界，不占 tick 临界区；此列是「编码」而不是「发送」。

### 2.8 LLM 预取调度（M1，异步量纲不进 tick，调度成本进）
- tick 内只承载确定性调度：触发门控评估（需求阈值/计划完成/受阻 2 次/空闲超时/收到念头/目击事件，§8）+ Intent 入队 + 执行时二次校验。
- LLM 网络往返（P95<8s、1.2–2k tok）是墙钟量纲，**不进本表**，见 `docs/perf/llm-monitoring.md`。
- 名义 0.05ms、上限 0.20ms：门控是常数级布尔检查，Intent 入队/校验 O(1)；若 L2 常驻 NPC 多、门控扫描变 O(N)，视实测回调。

### 2.9 嗅觉传播（M2 新通道，∝1/r² + 风向主导 + 持续源）
- 通道模型（DESIGN §7）：∝1/r² 衰减 + 风向主导 + 需持续源；与现有感知引擎（`sim/perception/propagation.py`「衰减+阻断+修正」三要素）同构，只换参数。
- **不做逐对**：∝1/r² 若逐对 50×50 计算是 O(N²)/tick（naive 哨兵实测 ~4.6ms，含风向投影更贵），且风场变化时要重算投影。
- **方案（Eulerian 网格增量扩散）**：活跃源每 tick 发射 → 整场平流（风，恒定风向 = 一次 `np.roll`）→ 衰减；接收端 O(1) 采样。扩散场隐式承载 1/r²，无逐对循环。参考实现 `sim/tests/bench/test_bench_smell.py::_SmellField`。
- **tick 内时序建议**：（1）源发射；（2）风场平流（若风非恒定，每 N tick 更新一次风场，帧内双线性插值平移，低频 pass）；（3）衰减；（4）接收采样（可与感知装配同帧，放在视觉之后）。始终在感知挂载点之后，不插入 tick 固定序中间（保证确定性 C5）。
- 名义 0.05ms、上限 0.15ms：实测（64×64、K=20 源、50 接收）扩散 ~0.009ms + 采样 ~0.001ms = **~0.01ms/tick**，远低于上限。上限留白给「风场非恒定→需双线性插值」情形。

## 3. 自洽性检查

- 合计名义 7.00ms ≤ 16.6ms ✓；合计上限 12.35ms ≤ 16.6ms ✓（M1 口径）。
- L1 + 感知 = 5.50ms 名义，占 78% 预算——M0–M1 优化主战场。
- 感知 3.00ms 为预算目标值，真实引擎暖态实测 3.0–3.3ms（贴线）；红线 3.6（+20% 慢机余量）。首轮 LOS 缓存冷启动 7.6–8.2ms 为一次性成本，bench 已 `warmup_rounds=1` 剔除（否则 mean 假红）。
- **M2 L1 + 嗅觉实测余量极大**：L1 实测定量（满载荷向量化 ~0.02ms）与嗅觉（~0.01ms）合计 ≪ 名义表 4.05ms；名义值按「未向量化写法 + 满属性 + 最坏节拍」保守留白，不改表。M2-P1 实测（`test_bench_l1_utility.py` / `test_bench_smell.py`）见 §2.4/§2.9。
- 4x 档 4.16ms 已低于名义合计 7.00ms ⇒ **4x/16x 不能靠「更快的 tick」实现**，必须走 §4 超速对策（降采样/合并 tick），避免用 100% CPU 追倍率。
- 战斗时间尺 1000ms/tick 与正常档完全解耦，预算互不竞争。

## 4. 超速对策（4x / 16x）

| 倍率 | 每 tick 预算 | 方案 |
|---|---|---|
| 1x | 16.6ms | 本表 |
| 4x | 4.16ms | 降采样：L1 每 4 tick 推进一次、感知每 2 tick；时钟/RNG/apply 全速 |
| 16x | 1.04ms | 合并 tick：内核按 60 tick 语义批处理，UI 按 960 tick/s 出帧；或接受「快进 = 低保真节拍」（文档宣告，不悄悄降质） |

**对账（F06，2026-09-20，真实引擎 50 NPC 实测）**：
- 感知视觉/听觉暖态 mean 3.0–3.3ms（红线 3.6，见 §2.5/bench）。1x 每 tick 全量 = 3.1ms，加时钟/RNG/apply/llm_sched ≈ 4.4ms 仍 < 16.6 ✓。
- **4x 必须降采样**：不降采样则 4x 每 tick 4.4ms > 4.16 预算 ✗。按「感知每 2 tick」均摊 3.1/2 = 1.55ms + 1.3ms ≈ 2.85ms < 4.16 ✓ · → 维持现节拍。
- **16x 必须合并 tick**：感知在 60 tick 语义批处理内一次全量（均摊 3.1/60 ≈ 0.05ms/tick），否则 1.04ms 预算逐 tick 跑不起；UI 帧率与模拟节拍解耦。

快进期间确定性不变（seed 相同 → 结果一致），只是节拍粒度变粗；回归线单列 4x/16x 阈值（见 bench-plan）。

**对账（M2-P1，2026-09-20，L1 效用 + 嗅觉推算）**：
- L1 满属性向量化 ~0.02ms + 嗅觉 ~0.01ms，相比 M1 合计（实际 ~4.4ms）增量可忽略；**M2 对 4x/16x 降采节拍无新增压力**。
- 4x 仍维持「感知每 2 tick」；L1 在 4x 按 §4 表应每 4 tick 推进——M2 L1 实测成本极低，即使不降采也 ~0.02ms/tick。降采档位由架构域（M2-A1）定，本域仅提供实测依据。

## 5. 采集与告警（量入为出，防回归）

- 每 tick 在 `structlog` 记：`perf.tick_ms`、各子系统分段计时（clock/rng/apply/utility/perception/snapshot/ws_encode/llm_sched）。
- LLM 侧监控独立：每次调用记 `tokens`/`latency_ms`，事件名与字段清单见 `docs/perf/llm-monitoring.md`（对齐 §15：单决策 <2k tok、决策延迟 P95<8s——墙钟量纲，与 tick 预算正交）。
- nightly 汇总：tick p99、p999、超预算秒数、各子系统占比；LLM 侧日汇总（per-profile tokens/latency P95 + retry + cache_hit）。超阈值告警进 CI 红灯（§bench-plan 阈值）。
