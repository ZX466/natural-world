# Workflow — 多 Agent 协作规范（.orca/workflow.txt）

> **每个 agent 行动前必须先读本文档**，找到自己负责的内容，不要越界。
> Claude 占主导，起组织作用。

## 1. 核心要点

- 每个能力域有一个 agent 负责，一个 agent 一个工作树。
- 每个能力域只指定一个推荐 Agent，不重复分配。
- Agent 注册表：`.orca/agent-registry.md`（内容仅由用户决定，不得随意更改；未覆盖能力保持空白，后续按需补充）。

## 2. 沟通规则（重要）

- **各 agent 之间尽量不要直接交流。**
- 通过各自工作树里的 `.orca/talking.txt` 间接留言（每个工作树都有）。
- 先不要通过 orca-cli 发信息。
- Claude 通过 talking.txt 分配任务；agent 通过 talking.txt 接受任务，接受后即执行。
- 每几轮对话，Claude 检查所有工作树的 `.orca/talking.txt`：删除没用的内容（避免干扰执行任务），同步精简版更新各工作树的 talking.txt —— **工作流一一对应**。

## 6. Context 管理

- 各 agent 上下文达到 **50%** 时提醒用户切换新对话，最大程度使用用户的 token。

## 7. 任务流转

1. Claude 分解任务 → 写入目标 agent 工作树的 `.orca/talking.txt`（任务内容 + 负责能力域）。
2. Agent 行动前读本文件 + agent-registry.md，确认任务属于自己 → 接受并执行。
3. 完成后在同一 talking.txt 回写结果（简短）。
4. 越界的任务不要做；不在注册表里的能力保持空白，等用户决定。
