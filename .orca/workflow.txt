# Workflow — 多 Agent 协作规范（.orca/workflow.txt）

> **每个 agent 行动前必须先读本文档**，找到自己负责的内容，不要越界。
> Claude 占主导，起组织作用。

## 1. 核心要点

- 每个能力域有一个 agent 负责，一个 agent 一个工作树。
- 每个能力域只指定一个推荐 Agent，不重复分配。
- Agent 注册表：`.orca/agent-registry.md`（内容仅由用户决定，不得随意更改；未覆盖能力保持空白，后续按需补充）。

## 2. 沟通规则（重要）

- **各 agent 之间尽量不要直接交流。**
- 通过各自工作树里的 `.orca/talking.txt` 间接留言（每个工作树都有）。
- 先不要通过 orca-cli 发信息。
- Claude 通过 talking.txt 分配任务；agent 通过 talking.txt 接受任务，接受后即执行。
- 每几轮对话，Claude 检查所有工作树的 `.orca/talking.txt`：删除没用的内容（避免干扰执行任务），同步精简版更新各工作树的 talking.txt —— **工作流一一对应**。

## 6. Context 管理

- 各 agent 上下文达到 **50%** 时提醒用户切换新对话，最大程度使用用户的 token。

## 7. 任务流转

1. Claude 分解任务 → 写入目标 agent 工作树的 `.orca/talking.txt`（任务内容 + 负责能力域）。
2. Agent 行动前读本文件 + agent-registry.md，确认任务属于自己 → 接受并执行。
3. 完成后在同一 talking.txt 回写结果（简短）。
4. 越界的任务不要做；不在注册表里的能力保持空白，等用户决定。

## 8. 记忆机制（memory.md，规则 #7）

- **每个工作树 `.orca/memory.md` 保存各自记忆**（tracked 入库；talking.txt 才是 gitignore 的本地件）：
  - 主树文件 = 六树**融合合集**（①Claude ②cline ③opencode ④codex ⑤pi ⑥kilo 分节）；
  - 各树本地副本是其对应节的**权威来源**，收编冲突时以各树版本为准，由 Claude（主导）分节融合。
- **新对话恢复序**（每树一致）：`.orca/talking.txt`（当前任务单）→ `.orca/memory.md` **自己那一节** → `.orca/workflow.txt` + `.orca/agent-registry.md`。
- **快照纪律**：每轮交付/收编后，在**自己节**顶部写一行快照 `【日期 轮次｜状态】做了什么/关键决定/坑/下一步`；旧快照压缩为 git log 指针（`git log --oneline -- .orca/memory.md` 可考古），不无限堆积。
- **写入即提交**：memory.md 改动走 `git add -f .orca/memory.md`（`.orca/` 被 catch-all ignore，已跟踪文件更新也须 -f）+ 常规提交；收编时 Claude 随主分支分发到各树。
- 收编流程随附动作：Claude 收编时把各树新快照融合进主树合集对应节，然后 `git merge main` 同步六树（冲突时各树本地版优先——即快照内容由原树裁决，但结构以 main 为主）。
